# 提示词手册（内置版，随插件分发）

> 由 `image_prompt_guide` 按需返回，不占常驻上下文。数据为本机实测（12 GB 级笔记本 GPU，多为单 seed），
> 是经验值；改内容后请重新复现。探索版见 [PROMPTS.md](./PROMPTS.md) 与 [MODEL.md](./MODEL.md)。
>
> 「官方 2512」指 Qwen 官方 `prompt_utils_2512.py` 改写器，仅作参考，不是 2.1 的硬约束。

工具：`image_generate`（t2i / 编辑 + `tier`）· `image_generate_raw`（任意工作流）· `image_workflow_inspect` ·
`image_upscale` · `image_process`（lean 档的像素处理：resize / mark_region / flatten_alpha / anim_encode / pose_check；
standard 档拆回五个独立工具）。

## 0. 三十秒选档

| 档 | 参数 | 耗时 | 用途 |
|---|---|---|---|
| `draft` | 1056² / 8 步（官方 turbo 协议，需 fast 包或本地 turbo LoRA） | ≈8–10 s | 试构图、迭代提示词；不适合含文字的终稿 |
| `standard` | 1536² / 25 步 | ≈48 s | 默认（省略 `tier` 时使用） |
| `quality` | 2048² / 40 步 | ≈170 s | 成片、带文字、写实 |

- 其他尺寸用 `width` / `height`（32 的倍数）。
- 编辑（带 `ref_images`）：局部换色/加配件 4–8 步够用；大幅改动用 25 步。
- 一次性任务加 `unload_after`：引擎驻留约 10.2 GB，`/free` 后约 1.2 GB。
- 提示词重写器（PE，仅网关模板 `*_pe`）：单张 9.75 GB 显存、耗时 ×10 以上，且会替调用方决定内容；
  agent 调用时按 §1 自己写更快也更省显存。
- seed 只在同尺寸/模型/步数下复现；切档或切尺寸会变构图，需要保构图时用放大或 i2i / `denoise`。

## 1. 写法：观察者描述，不堆关键词

```
主体（是什么/几个）→ 场景 → 风格 → 构图与光线 → 图内文字（要出字才写）
```

- 提交的是一段连贯描述；上面的骨架只用于规划，不要原样提交方括号或逗号标签。
- 首句定画种与主体，风格词只出现一次；再用 8–14 个方位短语覆盖四角与中心，不要挤在中间。
- 颜色带修饰词（深藏青/灰橄榄/淡奶油），材质写具体（拉丝金属/磨砂玻璃/粗麻）；光照单独成句，结尾收构图。
- 长度：T2I 一般 60–150 词，复杂画面 150–250 词；一句标签过短，会丢细节。
- T2I 用观察者视角陈述成品；编辑写「改什么、留什么」，不要重写整张画面。
- 提示词里不出现 Markdown 列表/编号/标题；画面文字用双引号逐字给出，并写位置/字重/颜色；
  画面无文字时写「画面中无任何可识别文字」；专有名词（人名、品牌、地名、网址）原样保留。
- 质量词 `8K`、`masterpiece`、`award-winning` 对 2.1 作用有限，不再追加。不写 `--ar`。
- 一次只处理一个目标：主体过多互相干扰，风格过多互相冲突。
- 构图先定机位与焦段再写内容：人眼高度 + 35–50mm + 站远拍全身就是随手拍。要两极化才出画面——
  贴地仰拍或正上方俯拍，16mm 广角畸变或 200mm 长焦压缩。
- 让场景的线替你构图：跑道白线、看台台阶、围栏立柱，从画面角汇向主体，比三分法有效。
- 主体占比二选一：贴脸顶天立地，或只占画面高度 1/5–1/4、其余留负空间。「人占一半站中间」是最平的构图。
- 加一当前景：贴地颗粒、草叶、栏杆、铁丝网虚化入画，制造前后纵深。
- 构图句写在最前面（画风之后、人物之前）：模型先定取景再填细节；`全身入画` 这类词会把极端取景拉回默认，
  极端机位则要补 `头顶留白，完整入画`，否则广角会把头裁掉。

## 2. 分类配方

不想每次重写观感句时，直接用 `image_generate(style="...")` 套现成骨架：
`realistic` / `anime` / `product` / `sticker` / `film` / `ink` / `flat` /
`clean-cel` / `design-dense`（只对文生图生效；
描述超过约 120 单元时只追加观感后缀，不重复前缀）。下表是自己写时的参照模板。

骨架只用于规划，提交前按 §1 展开为连贯描述。

写实照片
```
一张写实照片：<主体>位于<环境>，85mm 镜头与浅景深，自然光，整体<色调>。
```
- 摄影术语提升质感，不直接提升锐度；要极限锐度用摇拍（主体清晰、背景水平动态模糊）。

二次元
```
一段赛璐璐上色的二次元插画：<角色>，干净线稿与平涂，背景为<平涂色块 + 平滑渐变>，<取景>。
```
- 必须显式指定背景，否则会偏向厚涂风格；`upper body` / `full body` 控制取景。
- 风格词分图层：`厚涂`、`笔触`、`颗粒` 是背景属性，写进总风格句就会污染人物，头发和衣服变脏、变碎。
  人物层写「整片色块、平滑渐变、细笔收边、不出现笔触与颜料堆叠」，环境再单独写「保留厚涂块面与笔刷痕」。
  现成骨架：`style="clean-cel"`。
- 细节分两类：制服结构（领口双线、胸袋、裙褶等距、扣环）该多，笔触（一根根发丝、布纹、折痕绒感）该少。
- 画面不单调靠元素，不靠笔触——补这五组：道具（转动的扇、垂落的电线、未关的门）、结构（板材拼缝、钉子、
  残破印刷品）、光（窗棂光斑、门缝暖光、悬浮颗粒）、层次（前景一段虚化的遮挡物斜穿）、角色（一个撞色配件）。
  现成骨架：`style="design-dense"`。
- 场景与动作互为理由：动作要能回答「她为什么在这里」——上楼就停步回头、拉扶手借力、刚踩上上一级台阶；
  给出三个支点（手、重心、视线），用「刚 / 正要 / 被叫住」这类瞬间词，再让环境参与动作（风吹动头发、
  光落在肩与台阶）。只写「站着看镜头」会变成背景板。
- 脸要写四层，缺一层就退回默认的平淡脸：骨相（脸型小巧圆润、下颌线柔和）→ 五官分件（杏形大眼、
  外眼角微下垂、上睫毛根根分明、深琥珀瞳孔带一点高光、鼻梁窄而挺、上唇有唇珠、嘴角轻轻上扬）→
  肤感（淡腮红、卧蚕、水珠、皮肤通透带血色）→ 情绪（视线落在画面外、眼神安静专注）。只写「美丽的脸」等于没写。
- 湿布写四件套：颜色加深、雾面半透、褶皱处高光、贴身垂落。白布另写内搭（`上衣内搭藏青色内衬`），
  湿后透出的是内衬；想收住透度就补「湿后转为不透明的雾面」。
- 水线要留标记：入水处一圈细白水环 + 水下轮廓因折射轻微错位；只写「浸在水里」读不出水感。
  水珠写载体与方向——`成串水珠沿纤维往下滑`、`顺着小腿流下来的水痕`；皮肤湿意靠「细密水珠 + 流痕 + 受光小亮点」三层。
- 两种布光配方：侧逆光最稳（光源在侧后方、轮廓光、水面反光从下方补亮下巴与锁骨）；硬侧光戏剧性最强，
  但必须配「背景是暗下去的墙」，否则白衣直接过曝。
- 大景别与材质抢预算：人物只占画面高度 1/3 时，水珠和缎面光泽到不了像素级——材质用中近景，全景只测光与层次。
- 拍开阔场景靠地平线：压到画面下 1/3、天空留足；再给齐三件——画面里可见的光源、水面或湿沙的反光当第二光源、低太阳的长阴影。
- 人物默认写成年（`二十余岁`），不写「少女 / 幼态」叠湿身制服的组合。
- 先定风格路线再调参数：舒适型（低信息密度、统一影调、极简构图）或冲击型（高锐度、超分增强）。
- 角色一致性走编辑模式；纯 t2i 三视图各视图会漂。
- 人物面貌写骨相与五件，不写「亚洲脸」「东方美」这类空词：鹅蛋脸偏窄、内双眼皮、眼型细长、
  黑棕色瞳孔、鼻梁适中且鼻头圆润、唇形偏薄；再叠 `淡妆素颜感`、`肤色偏暖黄且清透`、`颊侧碎发`。
  年龄也靠骨相说（`二十五岁上下`），想更年轻只改骨相，不叠「少女」这类词。
- 肤色是独立变量，两种写法不能混：
  白皮写 `白皙细腻、偏冷调、受光处几乎不泛红的清透感`（只写「白皙」会偏黄偏亮）；
  晒黑靠晒痕不靠变深——`小麦色 + 鼻梁与颧骨晒红 + 汗光微亮 + 袖口与袜口浅一圈的晒痕`，
  只写小麦色会被读成天生深肤色。肤色句放在场景与光之后、画风句之前，它依赖受光信息，放前面会被后面的光照重写。
- 动态要写瞬间，不写状态：「跑步」「奔跑」只给到慢跑，写成 `双脚离地的腾空瞬间`、`后腿小腿抬向臀部`、
  `手臂大幅前后摆动`、`马尾与衣摆被风拉向后方` 才有动势；再补地面接触影（`脚下影子紧贴脚底、边缘清晰`），
  否则人物像贴在背景上。二次元比写实更依赖幅度词——写实有凝固的肌肉线条，二次元只能靠姿势本身。
- 裙装跑动要压住「飞跃」先验：写 `步幅不大、两腿交替一前一后、膝盖微屈、脚尖朝前`，并删掉「腾空 / 飞跃 / 跨步」，
  否则会出腾空劈叉。
- 复杂服装按层写，每层只给 1–2 个可指认构件：外套（校徽 + 肩章）→ 衬衫（尖领 + 条纹领带 + 翻出的袖口）→
  开衫（罗纹收口）→ 裙（细褶 + 裙摆白线）→ 袜 → 鞋 → 配件（书包铜环 + 学生证）；每层给材质
  （缎面 / 薄纱 / 皮革 / 刺绣 / 金属），配色一个主色加一个点缀色。细节吃景别：中近景能画对十来个构件，
  全身远景里校徽会退成金色色块、证件上的字变成白条。
- 对称件单独声明：`左右袜口高度一致`、`两只鞋成对`；动态里最常见的崩点就是左右不对称。

清新日常
```
一张写实照片：<角色>在<生活场景>，<三层材质对比 + 使用痕迹>，清晨侧窗光，浅景深。
```
- 清新不等于少细节，细节来自结构与使用痕迹：贴手写标签的玻璃罐、压花标本纸、铜柄小剪、磨亮的铜件、明线与水洗痕。
- 低饱和配色（白 + 浅绿 + 奶油黄）里只允许一个点缀色（陶土橘、芥末黄）落在配件上。
- 细节上限：中景 10–14 个元素，全身 5–6 个；再多就互相抢像素、糊成一片。
- 写实真实性门槛：皮肤有毛孔与细小绒毛、睫毛成簇、指甲与指节有结构、织物有织纹与明线。

3D / 产品
```
一件 3D 收藏手办：<主体>，PVC 光泽与布料哑光，影棚柔光，产品摄影，浅景深，置于<台面>。
```
- 纯产品换「材质台面 + 中性背景 + 柔光箱顶光」。
- 不要从 512² 起：512 → 1056² 时主体锐度与主体/背景比都明显改善。

海报 / 带文字
```
一张<风格>海报：顶部粗体<颜色>标题写着 "<文字>"，<次要文字与位置>，<插图区域>；
光线是…，整体构图是…。
```
- 先定版式，再处理文字；比例用数值（单字宽约画宽 7%，文本列宽 15–18%）。
- 更稳的路线：先生成无字底图，再后处理，最后在设计层加字（放大或后处理会让小字软化）。

透明贴纸 / 图标
```
这是一张 RGBA 透明背景的图：<主体>完整居中，不向背景投射阴影。
```
- 抠图提示词：`Remove the background, and output a PNG image`。输入先扁平化（管线输出的 RGBA 常带 alpha 噪声，会干扰抠图）。
- 小图用 512² 直出 + 2× 超分，比 2048² 直出再缩小更好也更快。

## 3. 文字渲染

| 档 | 配置 | 何时用 |
|---|---|---|
| 起步 | 25 步 | 无文字，或十余行小字先试 |
| 升档 | 40 步 | 25 步出现错字/幻觉字块时（同 seed 下 OCR 正确率更高） |
| 排版 | `cfg 2` + 40 步 + 负向词 | 密集小字/价目表；代价约 1.2–2.4× 时间 |

- 先 25 步，按结果升 40 步；不要一律 40 步，也不要固定 25 步。
- 错字分两类：幻觉字块（排版档可抑制）与字符级混淆（`1`↔`)`、`0`↔`O`）。后者同 seed 两档都会错，
  换 seed 或把数字改写成汉字。
- 生僻字不要只靠一次 OCR：多次读数、位置与提示词引用交叉验证。
- 分辨率远超模型训练尺度时会降低提示词遵循度。

### 海报与物料

海报有两条路线，不要指望一条走通：

| 路线 | 做法 | 适用 | 代价 |
|---|---|---|---|
| 直出 | 提示词里写标题、副标题、规格、价格，一次出整张 | 氛围草稿、看方向 | 文字能对，版式不可控：边距、字距、层级、换行位置都由模型决定；改一个字要整张重跑（quality 档约 4–5 分钟） |
| 合成 | 先出无字主视觉与产品图，再用排版脚本拼（逐字量宽做字距，渐变/暗角/颗粒用 NumPy） | 终稿、多尺寸、多风格 | 需要脚本与字体；换来版式完全可控、产品区画质不降 |

- 产品必须单独生成、单独验收：同一张图里既排字又画复杂结构，两件事互相抢注意力，结构崩得比平时快。
- 版式硬参数（1440×2160 起）：安全边距 ≥ 画布宽 7%；三级字号约 3:1:0.6（主标题/副标题/规格）；底部信息行离底边 ≥ 8%；中文大标题用细长衬线或加粗黑体二选一，不要中间态。
- 单张内文字量：标题 ≤ 8 字、副标题 ≤ 20 字、规格行 ≤ 3 项。超了既掉正确率，换行也由模型随手决定。
- 中英混排要按段换字体：西文字体不含汉字，整行用它会出方块；按 run 分段渲染。
- 同一张主视觉能切多种风格：极简（留白 + 竖排标题）、戏剧（双行大标题 + 衬线）、惊悚（红黑双色调 + 分级框）、霓虹（洋红青映射 + 扫描线 + 标题色散）。风格差异主要来自排版与调色，不是重新生成。
- 合成时把主视觉自身大模糊（半径约画布宽 7%、亮度压到 0.6）当底，产品区贴回去不会出现拼接边。

### 真实在售产品

- 品牌与型号是外形锚点：不点名时模型会混代次（把上一代的开孔、头梁套管拼到新一代上）；点名后配色与配置基本到位。
- 结构仍会漂：耳罩内外朝向（两个外壳同时朝向镜头）、穹顶弧度、头梁接缝、白色伪丝印、logo 比例。提示词要写「一个耳罩外壳朝向镜头、另一个露出耳垫内圈」，再用识别点（装饰环、开孔排布、接口位置）逐项验收。
- 结论：直出的产品图是氛围图，不是产品图；商用还有商标与外观风险，只适合技术测试与概念草图。

## 4. 参考图编辑

- 编辑提示词 = 变更 + 保留：「把 <image1> 的领结换成深蓝色，保持脸、发型、姿势和背景不变。」
  不要把 T2I 的长画面描述搬过来。
- 属性细化到部件（内耳、外耳、领结、裙边），易漂移的加 `MUST stay`；没写进提示词的属性由模型自行决定。
- 用正向状态代替否定句（`双手自然垂在身侧，掌心空着`、`画面只有一个角色`）。要排除时用
  `negative_prompt`（cfg > 1 生效）；「无任何道具」这类否定词可能反而引入对象。
- 多图分工：`<image1>` 只负责角色，`<image2>` 只负责风格或背景；每次只改一个层级。
- 同一角色只给一张权威参考，多角度参考会「复制」角色；要变姿势用文字描述。
- 参考图里的文字不要写风格断言（`anime style` 会把 Q 版带偏）。
- 纯白底参考会让场景偏白。两段式：先生成干净角色，再单独换背景。
- RGBA 输入会继承 alpha 噪声（背景颗粒），先用 `image_flatten_alpha`。
- 参考图必须是像素级真相：从自己的设计稿图层取素材，不要靠打标/看图描述推断。
- 局部修复用 `image_mark_region` 画红圈，指令给硬边界：
  `must stop strictly at the circle boundary and must NOT spread outside`，并声明红圈不出现在成图；
  软措辞（`inside the circle`）会向外泄漏。
- 复杂动作拆成可验证锚点（坐深、躯干角、腿伸向、手位、头仰角、眼开度、嘴形）。
- 大幅姿势变化是概率性失真：小步链式编辑或多参考；交付前双种子候选、逐项验收。
- 只改局部或保结构：单图 + `denoise` 0.7–0.9（0.45 只能打磨，改不了颜色）。`denoise` 不减耗时，
  要更快就减步数；`denoise 0.5` 加「更锐」会过度锐化。
- 角色一致性分两层：服装、配色、场景靠「逐条重复的分层清单」稳住，人脸靠像素。
- 固定 seed 锁的是风格、光照与配色，不锁身份：同一 seed 拍四个景别，会得到「同一类型的四个人」。
  脸占画面越小越回退默认脸——近景约 40% 有骨相，全身 8–10% 直接换成另一张更年轻的脸。
- 图生图保脸但锁景别：拿中景当参考图出「全身」，脸还是那个人，构图仍然是中景。要跨景别同脸只能另想办法。
- 多参考图必须走编辑模板：`denoise < 1` 只接受一张 init 图，传两张会直接报错。
- 参考图编辑不继承参考图的画风：prompt 里要显式写画风（`二次元动画插画、赛璐璐上色、不出现写真质感`），
  否则会被拉成半写实 CG；编辑模板还会把成品压到 1056²，要出成品图得再走一次 t2i。
- 可靠度排序：一张大图裁分镜（唯一像素级同脸）> 定妆图当参考做同景别变体 > 编辑模板换姿势（接受脸微漂）
  > 纯 t2i 多镜头。

## 5. 放大与后处理

顺序：渲染 → 局部修复 → 2× 超分 → 降采样回目标尺寸。
超分自带锐化，之后不要再叠 USM；×2 很快（1056²→2112² 约 5 s）。

| 内容 | 引擎 | 倍率 / 降噪 |
|---|---|---|
| 二次元（最锐） | `cugan_pro` | ×2/×3，降噪 0 或 3 |
| 二次元要 ×4 / 兼容 | `cugan` | ×2/×3/×4；×2 降噪 0–3，×3/×4 仅 0/3 |
| 保真、保笔触 | `waifu2x` | ×2，降噪 0 |
| 写实照片 | `waifu2x_photo`；打印 `photo_hq` | ×2；×4 |
| 明显劣化图（噪声 + JPEG 块） | `cugan` | ×2，降噪 1–3 |

- 降噪 1/2 只有 `cugan` ×2 开放；`cugan` ×3/×4 与 `cugan_pro` 仅 0/3；`waifu2x` 系固定 0。
- 类型匹配比引擎家族重要：动漫模型用在照片上垫底，照片模型用在动漫上无增益。
- 干净图降噪用 0，`3` 会断崖掉细节；名字带「保守」不等于结构保守，先小图试。
- 文字密集的小字不要放大（会软化变形）；交付优先直接给 2× 原图让屏幕超采样。
- 透明成品先扁平化再放大（本插件不做 alpha 检测）。

## 6. 动图 / 多帧

- 8 帧适用于局部动作；全身位移从 16 帧起。
- 每帧从同一参考独立生成：链式编辑会逐帧累积 VAE 有损往返（尾帧变暗发糊）。
- 动作措辞夸张 2–3 倍（「身体大幅倾斜」），否则同 seed 会收敛成同一张图。
- 逐帧时长：预备/滞空 110–120 ms，爆发/下落 50–70 ms。
- 合成用 `anim_encode`（lean 档为 `image_process(action="anim_encode")`）：WebP q88 优先；微信里用 512² GIF（`max_size=512`）。

## 7. 能力边界

- 像素预算：内容峰值约 4 MP；超过 8 MP 只增加画布面积，细节不再增加；单边不超过 4096。
  二次元约 1.1 MP 就接近饱和，写实到 2048²（4.2 MP）仍有收益。
- 「4 MP 直出 + 超分」优于「8 MP 直出再缩」；拼接合成不可行（两次独立生成的透视/桌沿线/窗位各自自洽）。
- 多 seed 没有共同真值：自由 t2i 帧间差异极大，朴素多帧平均会变糊。
- 编辑是全图重绘，不是图层合成：背景区也会变；要真图层得局部注入或后期合成。
- 三视图会漂；骨架控制需外部 ControlNet（插件只提供 `pose_check` 校验）：
  骨架要黑底粗白线、实心白头、无地面线/箭头，重心校准到画面高度 0.37–0.42。
- 显存：12 GB 上「角色参考 + 控制网 + 骨架」已逼近极限。
- 面部细节吃构图：胸像（头到胸口）脸占画面约 1/3 才够画睫毛与瞳孔；七分身以上脸部只剩百来像素，写多细的五官也救不回来。
- 细节随景别衰减：同一份复杂服装清单，中近景能落地十来个构件，全身只剩三四个大块，其余糊成纹理。
- 动态里的对称件只对一半是常态：袜口高度、两只鞋的鞋扣、左右袖口最容易不一致，靠提示词声明而非寄望模型。
- 固定 seed 不保证同一张脸：跨镜头一致性要靠裁切分镜或参考图编辑（见 §4）。
- 直出海报的版式不可控：边距、字距、层级、换行由模型决定，不能当排版稿去改一个字；要可控就走「主视觉 + 脚本排版」。
- 产品图的天花板是氛围图：真实在售产品的结构（内外朝向、接缝、丝印、logo 比例）会漂，点名型号只锁代次与配色，不锁结构。
- 一张图里同时要「排字」和「复杂产品结构」会双输：文字抢注意力，结构就崩；拆成两张再合成。

## 8. 排查速查

| 症状 | 先查 |
|---|---|
| 出图与参考完全无关 | 模板是否为 t2i（会忽略 `ref_images`）；参考图是否真的传入 |
| 角色颜色漂 | 属性没枚举到部件粒度；加 `MUST stay`、提步数、换 seed |
| 多出角色/道具 | 没写正向状态（`画面只有一个角色`）；参考图本身带了配角或手持物 |
| 背景颗粒/发脏 | RGBA 图直喂；先扁平化或提高预算 |
| 脸平淡、不好看 | 没写五官层：按 §2 的骨相 → 五官分件 → 肤感 → 情绪补齐，并换成胸像 |
| 湿材质看不出湿 | 缺「水线标记 + 水珠载体与方向」；或景别太远，人物占画面不到 1/3 |
| 构图平淡像随手拍 | 机位、焦段、主体占比都用了默认值：改贴地仰拍或正上方俯拍，16mm 或 200mm，占比别取中间值 |
| 跑动姿势变成腾空劈叉 | 触发了「飞跃」先验：改成 `步幅不大、两腿交替一前一后`，删掉「腾空」 |
| 左右袜口、两只鞋不一致 | 补 `左右袜口高度一致`、`两只鞋成对` |
| 同一个角色跨图换了张脸 | seed 不锁身份：改为裁切分镜，或用参考图走编辑模板（见 §4） |
| 海报文字对、但产品结构崩 | 拆两步：产品图单独出并验收，再用脚本排版（见 §3） |
| 海报边距挤、字距乱、层级不分明 | 直出只当草稿，交付走后期排版（见 §3） |
| 点名的真实产品画错代次/伪丝印 | 品牌名只锁代际：补内外朝向句与识别点，逐项验收（见 §3） |
| 文字错字 | 升 40 步 → `cfg 2` → 换 seed；数字改汉字 |
| 画面偏软但细节充足 | 缺少中频边缘对比；用 `cugan` ×2，而非 USM |
| 编辑后整体偏色/变软 | 多轮编辑累积；回退到原始参考重来 |
| 报错含 `CUDA out of memory` / 显存不足 | 走下面的降档阶梯；重启引擎通常没用 |
| 报错含 VBAR / Virtual Address space | 虚拟地址空间碎片化，不是显存不足：重启引擎 |

**显存不足降档阶梯**（从便宜到贵逐级试，每级都能出图，只是细节与分辨率下降）：

1. `tier="draft"`：1056²、8 步 turbo，显存约为 standard 的一半。
2. 降尺寸：`width` / `height` 从 1536² 降到 1024²（内容峰值 ≈4 MP，别硬堆像素）。
3. 参考图减量：3 张 → 1 张（编辑模板按张数走 edit / edit3 / edit6，张数越多越吃显存）。
4. 用完即卸：`unload_after=true`，下一次调用重新加载（多花 7–20 秒，不占常驻显存）。
5. 关掉其它占显存的程序再试；仍失败才重启引擎并重跑。

## 9. 边界实验方法

固定 seed，每次只改变一个维度：文字长度 4 → 8 → 12 → 20 → 30 字；主体数量 1 → 2 → 3 → 5；
尺寸 × 步数 1056²/1536²/2048² × 8/25/40；放大是否值得（×2 对比原生 2048²）。

记录 `提示词 / 尺寸 / 步数 / seed / 结论（能、不能、边界）`。单张图不算结论，用 3–5 个 seed 或 3 类内容复现后再写入。

## 10. 什么时候不该用

- 换背景：单图直换易出抠图光晕；用两段式（先干净角色，再换背景）。
- 换脸 / 身份保持：保不住与参考完全一致；用单一权威参考 + 只改局部。
- outpaint / 扩画布：不可靠，容易加黑边或重复结构；直接生成目标尺寸。
- 一次生成长文案：超过约 20 字就分批生成或后期排版。
- 超大尺寸：单边超过 4096、内容峰值超过约 4 MP 后收益很低，还容易重复结构。
- 透明图放大：`image_upscale` 不检测 alpha，可能静默丢透明；先扁平化或放大后自行合成。
- 多轮连续编辑：会累积偏色/软化；关键节点回到原始参考重来。

## 11. 分镜脚本

把剧本变成一组可拍的图，交付物是「镜头表 + 每镜一格图」，不是一张漂亮插画。

| 步骤 | 产出 | 要点 |
|---|---|---|
| 拆镜 | 镜头表：镜号/时长/景别/机位/焦段/画面一句话/台词要点/转场 | 先定时长再定景别：3 秒以内只够一个动作；快闪 1.2 秒/镜，靠同机位换装省资产 |
| 出图 | 每镜一张 16:9（1536×864） | 每镜单独 t2i，角色设定清单逐条重复；不要在一张图里塞两个镜头 |
| 钉板 | 2 列 × N 行总图 | 用来看节奏：哪里该切、哪里停留过长 |
| 文档 | A4 横向，每页一镜：左图右注（运镜/画面/台词/音效/3D 备注/转场） | 末尾附镜头总表与落地说明（资产优先级、可复用镜头、口型需求） |

- 转场与声音也是分镜内容：敲门声可前置 6 帧再硬切；关门瞬间切黑；笑声用「声音延续 + 切到门板」表现，比画一个人形省钱也更好笑。
- 3D 三渲二写法：赛璐璐平涂 + 柔和轮廓光 + 皮肤次表面 + 布料与金属细节。不要写「2D 动画」「手绘」，会把质感拉成平面。
- 一镜只给一个动作动机；焦段写进表里照抄：POV 用 35mm 轻广角，过肩 50mm，情绪特写 85–100mm。
- 分镜之间的人物一致性靠同一份设定清单（逐条重复）加裁切分镜；seed 只锁风格与光照（见 §4）。
- 镜头数按秒数估：50 秒短片 12–16 镜。少于此会拖，多于此在 12 GB 上出图时间不可接受。
