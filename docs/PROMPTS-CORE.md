## 0. 三十秒选档

| 档 | 参数 | 耗时 | 用途 |
|---|---|---|---|
| `draft` | 1056² / 8 步（官方 turbo 协议；需 fast 包或本地 turbo LoRA，缺失时返回错误） | ≈8–10 s | 试构图、迭代提示词；画质接近 standard，但不适合含文字的终稿 |
| `standard` | 1536² / 25 步 | ≈48 s | 默认（省略 `tier` 时使用此档） |
| `quality` | 2048² / 40 步 | ≈170 s | 成片、带文字、写实 |

- 其他尺寸直接使用 `width` / `height`（32 的倍数）；`tier` 仅预设上述三个尺寸。
- 编辑（带 `ref_images`）：局部换色或添加配件使用 4–8 步即可；大幅改动使用 25 步。
- 一次性任务加 `unload_after`：引擎驻留约 10.2 GB，`/free` 后约 1.2 GB。
- 提示词重写器（PE，仅外部网关模板 `*_pe`）：单张要 9.75 GB 显存、耗时 ×10 以上，实际会替调用方决定内容。
  调用方为 agent 时，按 §1 编写长提示词通常更快，也更节省显存。
- 同一 seed 只在相同尺寸/模型/步数下复现；切换档位或尺寸后构图会变化；需要保留构图时使用放大或 i2i / `denoise`。

## 1. 写法：观察者描述，避免关键词堆叠

```
主体（是什么/几个）→ 场景 → 风格 → 构图与光线 → 图内文字（要出字才写）
```

- 最终提交的是一段连贯描述。下列标签与骨架仅用于规划，不要原样提交方括号或逗号标签。
- 首句定画种与主体，风格词只出现一次；再使用 8–14 个方位短语覆盖四角与中心，不要集中在中间。
- 颜色带修饰词（深藏青/灰橄榄/淡奶油），材质写具体（拉丝金属/磨砂玻璃/粗麻）；光照单独成句，结尾一句收构图。
- 长度：T2I 一般 60–150 词，复杂画面 150–250 词；官方 2512 改写器约 200 词，社区 2.1 skill 写 400–500 词。
  本机实测更注重描述的具体程度，长度本身不是决定因素；过短（仅一句标签）容易丢失细节。
- T2I 与编辑分开描述：T2I 描述成品画面，使用观察者视角与陈述句；编辑说明改动内容与保持不变的部分，不要重写整张画面。
- 格式要求：最终提示词里不要出现 Markdown 列表/编号/标题；画面文字用双引号逐字给出，并写位置/字重/颜色；
  画面没有文字时明确写「画面中无任何可识别文字」；专有名词（人名、品牌、地名、网址）原样保留。
- 质量词：`8K`、`masterpiece`、`award-winning` 对 2.1 效果有限，官方 2512 已不再追加。用户明确要求 4K 或超清时可以保留，但会占用提示词语义。不要写 `--ar`。
- 一次只处理一个目标：主体过多会相互干扰，风格过多会相互冲突。

## 2. 分类配方

以下为骨架。提交前展开为连贯描述，不要保留方括号或逗号标签。

写实照片
```
一张写实照片：<主体>位于<环境>，85mm 镜头与浅景深，自然光，整体<色调>。
```
- 摄影术语主要提升照片质感，不直接提升锐度；需要极限锐度时使用摇拍描述（主体清晰、背景水平动态模糊）。
- 胶片颗粒会制造假高频，跨风格比较时不可信。

二次元
```
一段赛璐璐上色的二次元插画：<角色>，干净线稿与平涂，背景为<平涂色块 + 平滑渐变>，<取景>。
```
- 必须显式指定背景，否则模型倾向于厚涂风格；`upper body` / `full body` 控制取景。
- 先确定风格路线，再调整参数：舒适型（低信息密度、统一影调、极简构图）或冲击型（高锐度、超分增强）。
- 角色一致性走编辑模式；纯 t2i 三视图各视图会漂。

3D / 产品
```
一件 3D 收藏手办：<主体>，PVC 光泽与布料哑光，影棚柔光，产品摄影，浅景深，置于<台面>。
```
- 纯产品换「材质台面 + 中性背景 + 柔光箱顶光」。
- 不要从 512² 开始：512 → 1056² 时主体锐度与主体/背景比均明显改善。

海报 / 带文字
```
一张<风格>海报：顶部粗体<颜色>标题写着 "<文字>"，<次要文字与位置>，<插图区域>；
光线是…，整体构图是…。
```
- 先确定版式，再处理文字；比例使用数值（单字宽约画宽 7%，文本列宽 15–18%）。
- 更稳定的工程路线：先生成无字底图，再后处理，最后在设计层添加文字（放大或后处理会使小字软化）。

透明贴纸 / 图标
```
这是一张 RGBA 透明背景的图：<主体>完整居中，不向背景投射阴影。
```
- 抠图提示词：`Remove the background, and output a PNG image`。输入不应包含 alpha 通道（管线输出的 RGBA 常含 alpha 噪声，影响抠图），应先扁平化。
- 小图不要采用「大尺寸生成后降采样」：512² 直出加 2× 超分，比 2048² 直出后缩小效果更好，速度也更快。
- 小尺寸的观感主要取决于中频边缘对比；堆叠高频细节会被看图软件降采样消除。

## 3. 文字渲染

| 档 | 配置 | 何时用 |
|---|---|---|
| 起步 | 25 步 | 无文字，或十余行小字可先尝试 |
| 升档 | 40 步 | 25 步出现错字/幻觉字块时（同 seed 下 OCR 正确率更高） |
| 排版 | `cfg 2` + 40 步 + 负向词 | 密集小字/价目表；代价约 1.2–2.4× 时间 |

- 先使用 25 步，再根据结果升到 40 步。不要一律使用 40 步，也不要在所有含文字任务中固定使用 25 步。
- 错字分两类：幻觉字块（排版档可抑制）与字符级混淆（`1`↔`)`、`0`↔`O`）。后者在同一 seed 的两档中均会出错，
  只能换 seed 或把数字改写成汉字。
- 没有「超过多少字必然失败」的统一阈值，可追溯的只有行数级案例。
- 生僻字不要只依赖一次 OCR：结合多次读数、位置与提示词引用交叉验证。
- 目标分辨率远超模型训练尺度时会降低提示词遵循度，分辨率并非越大越好。

## 4. 参考图编辑

- 编辑提示词 = 变更 + 保留：`把 <image1> 的领结换成深蓝色，保持脸、发型、姿势和背景不变。`
  不要把 T2I 的长画面描述原样搬过来。
- 属性枚举：颜色细化到部件（内耳、外耳、领结、裙边），易漂移的属性加 `MUST stay`。未写入提示词的属性由模型自行决定。
- 优先描述正向状态，避免堆叠否定句：道具、配角、宠物与背景杂物会被继承，但「无任何道具 / 无吉祥物」
  这类否定词可能反而引入对象（官方旧版改写器要求改写后不出现否定词）。更稳定的写法是描述正向状态
  （`双手自然垂在身侧，掌心空着`、`画面只有一个角色`）；需要排除时使用 `negative_prompt`（cfg > 1 时生效）。
- 多图职责：`<image1>` 只负责角色，`<image2>` 只负责风格或背景；每次只修改一个层级。
- 单一权威参考：同一角色多张不同角度参考会「复制」出多个角色；要变姿势用文字描述。
- 参考图里的文字不要写风格断言（`anime style` 会把参考图的 Q 版带偏）。
- 纯白底参考会使场景偏白。采用两段式流程：先生成干净角色，再单独更换背景；更换背景是保留角色较稳定的路径。
- 直接输入 RGBA 会继承 alpha 噪声（背景颗粒）。应先使用 `image_flatten_alpha`，或通过高预算重采样同时平均噪声。
- 参考图必须是像素级真相：从自己的设计稿图层取素材，不要靠打标/看图描述推断。
- 局部修复用 `image_mark_region` 画红圈，指令必须给硬边界：`must stop strictly at the circle boundary and must NOT spread outside`，
  并声明「红圈不出现在成图」；软措辞（`inside the circle`）会向外泄漏。
- 复杂动作拆分为可验证锚点（坐深、躯干角、腿伸向、手位、头仰角、眼开度、嘴形），比笼统的「瘫坐伸腿」更可控。
- 大幅姿势变化是概率性失真（单次通过≠普遍成立）：小步链式编辑或多参考；交付前双种子候选、逐项验收。
- 只改局部或保留结构：单张初始图加 `denoise` 0.7–0.9（0.45 无法改变颜色，仅能打磨）；`denoise` 不会减少耗时，需要更快时减少步数。
  自精修 `denoise 0.5` 并加入「更锐」措辞会导致过度锐化（实测失败）。

## 5. 放大与后处理

顺序：渲染 → 局部修复 → 2× 超分 → 降采样回目标尺寸。
超分自带锐化，之后不要再叠 USM（叠加 = 过锐）。超分 ×2 很快（1056²→2112² 约 5 s）。

| 内容 | 引擎 | 倍率 / 降噪 |
|---|---|---|
| 二次元（最锐） | `cugan_pro` | ×2/×3，降噪 0 或 3 |
| 二次元要 ×4 / 兼容 | `cugan` | ×2/×3/×4；×2 降噪 0–3，×3/×4 仅 0/3 |
| 保真、保笔触 | `waifu2x` | ×2，降噪 0 |
| 写实照片 | `waifu2x_photo`；打印 `photo_hq` | ×2；×4 |
| 明显劣化图（噪声 + JPEG 块） | `cugan` | ×2，降噪 1–3 |

- 降噪 1/2 只有 `cugan` ×2 开放；`cugan` ×3/×4 与 `cugan_pro` 仅 0/3；`waifu2x` 系固定 0。
- 类型匹配比引擎家族重要：动漫模型用在照片上垫底，照片模型用在动漫上无害也无增益。
- 干净图降噪用 0；`3` 会断崖掉细节；名字带「保守」不等于结构保守（先小图试）。
- 本插件不做 alpha 检测：透明成品先扁平化再放大，或 RGB 放大后自行合成 alpha（后者未实测）。
- 文字密集的小字不要放大（会软化变形）。交付优先直接给 2× 原图让屏幕超采样。

## 6. 动图 / 多帧

- 8 帧适用于局部动作；全身位移从 16 帧起。
- 每帧从同一参考独立生成：链式编辑会逐帧累积 VAE 有损往返（尾帧变暗发糊）。
- 动作措辞夸张 2–3 倍（「身体大幅倾斜」），否则同 seed 会收敛成同一张图、动作被吞掉。
- 逐帧时长：预备/滞空 110–120 ms，爆发/下落 50–70 ms（节奏感比统一帧率重要）。
- 合成用 `anim_encode`：WebP q88 优先；微信里用 512² GIF（`max_size=512`）。
- 电影级流畅属于视频模型能力；在表情包尺度，帧间轻微变化可以接受。

## 7. 能力边界

- 像素预算：内容峰值约 4 MP；超过 8 MP 后仅增加画布面积，内容细节不再增加；单边不超过 4096。
  二次元约 1.1 MP 就接近饱和，写实到 2048²（4.2 MP）仍有收益。
- 大画布的单位像素细节会被稀释 → 「4 MP 直出 + 超分」优于「8 MP 直出再缩」。
- 拼接合成不可行：两次独立生成的透视/桌沿线/窗位各自自洽，羽化与接缝重绘救不了。
- 多 seed 没有共同真值：自由 t2i 帧间差异极大，朴素多帧平均会变糊。
- 编辑为全图重绘，不是图层合成：背景区也会变；要真图层得局部注入或后期合成。
- 三视图会漂；骨架控制需外部 ControlNet（插件只提供 `pose_check` 校验）：
  骨架要黑底粗白线、实心白头、无地面线/箭头，重心校准到画面高度 0.37–0.42。
- 显存限制：12 GB 上「角色参考 + 控制网 + 骨架」已逼近极限。

## 8. 排查速查

| 症状 | 先查 |
|---|---|
| 出图与参考完全无关 | 模板是否为 t2i（会忽略 `ref_images`）；参考图是否已实际传入 |
| 角色颜色漂 | 属性没枚举到部件粒度；加 `MUST stay`、提步数、换 seed |
| 多出角色/道具 | 没写正向状态（`画面只有一个角色`）；参考图本身带了配角或手持物 |
| 背景颗粒/发脏 | RGBA 图直喂；先扁平化或提高预算 |
| 文字错字 | 升 40 步 → `cfg 2` → 换 seed；数字改汉字 |
| 画面偏软但细节充足 | 缺少中频边缘对比；使用 `cugan` ×2，而非 USM |
| 编辑后整体偏色/变软 | 多轮编辑累积；回退到原始参考重来 |

## 9. 能力边界实验方法

固定 seed，每次只改变一个维度：

1. 文字长度阶梯：4 → 8 → 12 → 20 → 30 字
2. 主体数量阶梯：1 → 2 → 3 → 5，看从第几个开始互相污染
3. 尺寸 × 步数矩阵：1056²/1536²/2048² × 8/25/40，判断「细节不足」是分辨率问题还是步数问题
4. 放大是否值得：`image_upscale` ×2 对比原生 2048²，区分「结构不足」与「只是不够锐」

记录格式：`提示词 / 尺寸 / 步数 / seed / 结论（能、不能、边界）`。
单张图不足以形成结论。使用 3–5 个 seed 或 3 类内容复现后，再写入文档。

## 10. 什么时候不该用

- 换背景：单图直接换背景容易出抠图光晕/边缘残留；更稳的是「先出干净角色 → 再单独换背景」两段式。
- 换脸与身份保持：模型保不住与参考图完全一致的身份；需要身份一致时用单一权威参考 + 只改局部。
- outpaint 与扩画布：不可靠，容易加黑边或重复结构；要更大画幅直接生成目标尺寸。
- 一次生成长文案：超过约 20 字就该分批生成或后期排版，不要指望一次出全。
- 超大尺寸：单边超过 4096、内容峰值超过约 4 MP 后收益很低，还容易重复结构。
- 透明图放大：`image_upscale` 不做 alpha 检测，可能静默丢透明；先扁平化或放大后自行合成 alpha。
- 多轮连续编辑：会累积偏色/软化；关键节点回到原始参考重来。
