# 提示词手册（核心版，随插件分发）

> 由 `image_prompt_guide` 工具返回，**不占常驻上下文**。数据来自本机实测（12 GB 级笔记本 GPU，多为单 seed），
> 是**经验值**不是模型定律，换内容请复现。更长的探索版见 [PROMPTS.md](./PROMPTS.md) 与 [MODEL.md](./MODEL.md)。

工具：`image_generate`（t2i/编辑 + `tier`）· `image_generate_raw`（任意工作流）· `image_upscale` ·
`image_resize_lanczos` · `image_flatten_alpha` · `image_mark_region` · `anim_encode` · `pose_check`

## 0. 三十秒选档

| 档 | 参数 | 耗时 | 用途 |
|---|---|---|---|
| `draft` | 1056² / 6 步（turbo LoRA，未随包） | ≈7 s | 试构图、迭代提示词；细节与文字弱 |
| `standard` | 1536² / 25 步 | ≈48 s | 默认 |
| `quality` | 2048² / 40 步 | ≈170 s | 成片、带文字、写实 |

- 其它尺寸直接给 `width`/`height`（32 的倍数），`tier` 只预设上面三个尺寸。
- 编辑（带 `ref_images`）：局部换色/加配件 4–8 步够用；大幅改动 25 步。
- 一次性任务加 `unload_after`：引擎驻留约 10.2 GB，`/free` 后约 1.2 GB。
- 提示词重写器（PE，仅外部网关模板 `*_pe`）：单张要 9.75 GB 显存、耗时 ×10 以上，本质是「替你做决定」——
  调用方是 agent 时，按 §1 自己写长提示词更快更省。

## 1. 写法：一句画面描述，不是关键词堆

```
主体（是什么/几个）→ 场景 → 风格 → 构图与光线 → 图内文字（要出字才写）
```

- 首句定画种与主体，风格词只出现一次；再用 8–14 个方位短语铺开四角与中心，别全堆中间。
- 颜色带修饰词（深藏青/灰橄榄/淡奶油），材质写具体（拉丝金属/磨砂玻璃/粗麻）；光照单独成句，结尾一句收构图。
- 陈述句优于祈使句；**不要** `8K`/`masterpiece`/`award-winning`（无效，只挤占语义），也不要 `--ar`。
- 图内文字：双引号逐字 + 位置 + 字重 + 颜色；中文再加「不得多字/漏字/错字/乱码」。
- 标签化短行（用途/主体/风格/构图/光照/色板/材质/文字/约束）比 200 词长段落更好改。
- 一次只追一个目标：主体多了互相污染，风格多了互相打架。

## 2. 分类配方

**写实照片**
```
[主体] 的写实照片, [环境], 85mm, 浅景深, 自然光, [色调]
```
- 摄影术语买到的是「照片感」不是锐度；要极限锐利用摇拍（主体清晰 + 背景水平动态模糊）。
- 胶片颗粒会制造假高频，跨风格比较时不可信。

**二次元**
```
[角色], 赛璐璐上色, 干净线稿, 平涂, [背景: 平涂色块 + 无笔触 + 平滑渐变], [取景]
```
- 背景必须主动指定，否则默认往厚涂抹走；`upper body`/`full body` 控制取景。
- 先定路线再调参：舒适型（低信息密度 + 统一影调 + 极简构图）或 冲击型（高锐度 + 超分增强）。
- 角色一致性走编辑模式；纯 t2i 三视图各视图会漂。

**3D / 产品**
```
[主体] 的 3D 收藏手办, PVC 光泽 + 布料哑光, 影棚柔光, 产品摄影, 浅景深, [台面]
```
- 纯产品换「材质台面 + 中性背景 + 柔光箱顶光」。
- 别从 512 上来：512 → 1056² 主体锐度与主体/背景比都明显变好。

**海报 / 带文字**
```
[风格] 海报, 顶部粗体 [颜色] 标题写着 "[文字]", [次要文字与位置], [插图区域],
the lighting is …, The overall composition …
```
- 先版式后文字；比例用数字（单字宽≈画宽 7%，文本列宽 15–18%）。
- 更要稳的工程路线：先生成无字底图 → 后处理 → 在设计层加字（放大/后处理会让小字软化）。

**透明贴纸 / 图标**
```
这是一张 RGBA 透明背景的图, [主体], 主体完整居中, 不向背景投射阴影
```
- 抠图话术：`Remove the background, and output a PNG image`；输入**必须无 alpha**（管线产出的 RGBA 自带 alpha 噪声，会抠不净），先扁平化。
- 小图别「大预算 + 降采样」：512² 直出 + 2× 超分，比 2048² 直出再缩更好也更快。
- 小尺寸观感取决于**中频边缘对比**，堆高频细节会被看图软件降采样抹平。

## 3. 文字渲染（最容易低估的一环）

| 档 | 配置 | 何时用 |
|---|---|---|
| 快 | 25 步 | 无文字，或十来行小字先试 |
| 稳 | 40 步 | 含文字一律先上（同 seed 下 OCR 正确率更高） |
| 排版 | `cfg 2` + 40 步 + 负向词 | 密集小字/价目表；代价约 1.2–2.4× 时间 |

- 错字分两类：**幻觉字块**（排版档能压掉）与**字符级混淆**（`1`↔`)`、`0`↔`O`）——后者同 seed 两档同错，
  只能换 seed 或把数字改写成汉字。
- 没有「超过多少字必崩」的统一阈值，可追溯的只有行数级案例。
- 生僻字别只信一次 OCR：多次读数 + 位置 + 提示词引用交叉验证。
- 目标分辨率远超模型训练尺度会丢提示词遵循——不是越大越好。

## 4. 参考图编辑

- **属性枚举**：颜色写到部件粒度（内耳/外耳、领结、裙边），易漂的加 `MUST stay`。没写进提示词的属性 = 模型自由发挥。
- **反向排除同样必须写**：道具、配角/宠物、背景杂物都会被当成角色的一部分继承
  → `双手空着，无任何道具` / `画面内只有一个角色，无吉祥物、无宠物`。
- **多图定职责**：`<image1>` 只负责角色，`<image2>` 只负责风格/背景；一次只改一层。
- **单权威参考**：同一角色多张不同角度参考会「复制」出多个角色；要变姿势用文字描述。
- 参考图里的文字**不要写风格断言**（`anime style` 会把参考图的 Q 版带偏）。
- 纯白底参考会把场景「拉白」→ 两段式：先出干净角色，再单独换背景（换背景是最稳的保角色路径）。
- RGBA 直喂会遇到 alpha 噪声被继承（背景颗粒）→ 先 `image_flatten_alpha`，或高预算重采样顺带平均掉。
- 参考图必须是像素级真相：从自己的设计稿图层取素材，不要靠打标/看图描述推断。
- 局部修复用 `image_mark_region` 画红圈，指令必须给**硬边界**：`must stop strictly at the circle boundary and must NOT spread outside`，
  并声明「红圈不出现在成图」；软措辞（`inside the circle`）会向外泄漏。
- 复杂动作拆成可验证锚点（坐深、躯干角、腿伸向、手位、头仰角、眼开度、嘴形），比「瘫坐伸腿」可控。
- 大幅姿势变化是概率性失真（单次通过≠普遍成立）：小步链式编辑或多参考；交付前双种子候选、逐项验收。
- 自精修时 `denoise 0.5` + 「更锐」措辞 = 过度锐化（实测翻车）。

## 5. 放大与后处理

顺序：渲染 → 局部修复 → **2× 超分** → 降采样回目标尺寸。
超分自带锐化，之后**不要**再叠 USM（叠加 = 过锐）。超分 ×2 很快（1056²→2112² 约 5 s）。

| 内容 | 引擎 | 倍率 / 降噪 |
|---|---|---|
| 二次元（最锐） | `cugan_pro` | ×2/×3，降噪 0 或 3 |
| 二次元要 ×4 / 兼容 | `cugan` | ×2/×3/×4，降噪 1–3 |
| 保真、保笔触 | `waifu2x` | ×2，降噪 0 |
| 写实照片 | `waifu2x_photo`；打印 `photo_hq` | ×2；×4 |
| 明显劣化图（噪声 + JPEG 块） | `cugan` | ×2，降噪 1–3 |

- 降噪 1–3 **只有 `cugan` ×2 档开放**；`cugan_pro` 仅 0/3；`waifu2x` 系固定 0。
- 类型匹配比引擎家族重要：动漫模型用在照片上垫底，照片模型用在动漫上无害也无增益。
- 干净图降噪用 0；`3` 会断崖掉细节；名字带「保守」不等于结构保守（先小图试）。
- 本插件**不做 alpha 检测**：透明成品先扁平化再放大，或 RGB 放大后自行合成 alpha（后者未实测）。
- 文字密集的小字不要放大（会软化变形）。交付优先直接给 2× 原图让屏幕超采样。

## 6. 动图 / 多帧

- 8 帧够局部动作；全身位移 16 帧起步。
- **每帧从同一参考独立生成**：链式编辑会逐帧累积 VAE 有损往返（尾帧变暗发糊）。
- 动作措辞夸张 2–3 倍（「身体大幅倾斜」），否则同 seed 会收敛成同一张图、动作被吞掉。
- 逐帧时长：预备/滞空 110–120 ms，爆发/下落 50–70 ms（节奏感比统一帧率重要）。
- 合成用 `anim_encode`：WebP q88 优先；微信里用 512² GIF（`max_size=512`）。
- 电影级丝滑是视频模型的领地，帧间「呼吸感」在表情包尺度可接受。

## 7. 能力边界

- **像素预算**：内容峰值约 4 MP，8 MP 之后买画布不买内容；单边别超 4096。
  二次元约 1.1 MP 就接近饱和，写实到 2048²（4.2 MP）仍有收益。
- 大画布的单位像素细节会被稀释 → 「4 MP 直出 + 超分」优于「8 MP 直出再缩」。
- **拼接合成不可行**：两次独立生成的透视/桌沿线/窗位各自自洽，羽化与接缝重绘救不了。
- **多 seed 没有共同真值**：自由 t2i 帧间差异极大，朴素多帧平均会变糊。
- 编辑是**全图重绘**不是图层合成：背景区也会变；要真图层得局部注入或后期合成。
- 三视图会漂；骨架控制需外部 ControlNet（插件只提供 `pose_check` 校验）：
  骨架要黑底粗白线、实心白头、无地面线/箭头，重心校准到画面高度 0.37–0.42。
- 显存墙：12 GB 上「角色参考 + 控制网 + 骨架」已逼近极限。

## 8. 排查速查

| 症状 | 先查 |
|---|---|
| 出图与参考完全无关 | 模板是不是 t2i（会吞掉 `ref_images`）；参考图是否真的传上去了 |
| 角色颜色漂 | 属性没枚举到部件粒度；加 `MUST stay`、提步数、换 seed |
| 多出角色/道具 | 反向排除没写；参考图本身带了配角或手持物 |
| 背景颗粒/发脏 | RGBA 图直喂；先扁平化或提高预算 |
| 文字错字 | 升 40 步 → `cfg 2` → 换 seed；数字改汉字 |
| 图看着糊但细节不少 | 缺中频边缘对比；用 `cugan` ×2 而不是 USM |
| 编辑后整体偏色/变软 | 多轮编辑累积；回退到原始参考重来 |

## 9. 想摸上限时的实验方法

固定 seed，一次只动一个维度：

1. 文字长度阶梯：4 → 8 → 12 → 20 → 30 字
2. 主体数量阶梯：1 → 2 → 3 → 5，看从第几个开始互相污染
3. 尺寸 × 步数矩阵：1056²/1536²/2048² × 6/25/40，判断「细节不足」是分辨率问题还是步数问题
4. 放大是否值得：`image_upscale` ×2 对比原生 2048²，区分「结构不足」与「只是不够锐」

记录格式：`提示词 / 尺寸 / 步数 / seed / 结论（能、不能、边界）`。
**单张图不算结论**——3–5 个 seed 或 3 类内容复现过，再写回文档。
