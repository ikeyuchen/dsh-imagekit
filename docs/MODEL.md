# 生图链路与参数手册

> 这份文档回答两个问题：**提示词到底被送到哪里、中间有没有被加工**，以及**模型有哪些参数、该怎么调**。
> 提示词怎么写见 [PROMPTS.md](./PROMPTS.md)；怎么用起来见 [USAGE.md](./USAGE.md)。

## 1. 提示词的真实链路

插件有两条出图链路。`generationBackend=auto`（默认）会**先探测外部网关**：在线就走网关，离线才用内置直连；也可以强制只用其中一条：

| 链路 | 何时使用 | 提示词怎么进模型 |
|---|---|---|
| **内置直连**（`auto` 且网关离线时自动使用） | 文生图 / 参考图编辑；无需外部服务 | 插件在 Node 里现场拼 ComfyUI API 工作流：`UNETLoader` + `CLIPLoader` + `CLIPTextEncode` → `KSampler` → `VAEDecode` → `SaveImage`；参考图编辑多一步 `/upload/image` + 编辑编码节点 |
| 外部兼容网关（旧模板） | `*_pe`（Prompt 增强）、`cn`（ControlNet）、`vnccs`、`turbo_official_edit` 等旧模板 | 网关按自己的模板文件把占位符替换成实际参数（模板不在本仓库） |

两条链路的共同点：**提示词最终都以文本进文本编码器**，所以本手册的参数与提示词结论对两条链路都成立；
区别只在「有没有 Prompt 增强、有没有额外控制网」。`generationBackend` 配置控制用哪条（见 [CONFIGURATION.md](./CONFIGURATION.md)）。

## 2. 采样参数

| 参数 | 默认 | 范围/取值 | 什么时候动 |
|---|---|---|---|
| `steps` | 25 | 4–50（官方 turbo 固定 8 步；turbo LoRA 回退 6 步） | 细节不够 +5~10；赶时间用 `draft` 档（turbo 8 步 ≈ standard，见 §5.3） |
| `cfg` | 1.0 | 1.0–3.0（实测） | 保持 1.0；2.0 更浓但耗时 ×1.5，3.0 不推荐（见 §5.2） |
| `width` / `height` | 由档位决定（draft 1056² / standard 1536² / quality 2048²） | 32 的倍数；模型原生 ≈4MP（2048²），官方比例表 2048²–2752×1536 | 默认档 1536²（25 步，12G 约 50 秒）；成片 2048²/40 步（约 170 秒）；草稿 1056²；**超过原生不建议**（2560² 25 步 226 秒且易重复） |
| `seed` | -1（随机） | 整数 | 复现同一张：填上次结果里的 seed |
| `batch_size` | 1 | 1–8 | 一次出多张再挑；显存占用线性增长 |
| `denoise` | 1.0 | 0.05–1.0 | **只对 i2i 有效**：0.4–0.6 只做轻微打磨，0.7–0.9 保结构改内容，1.0 完全重画 |
| `resolution` | 1056（t2i 忽略） | 512–2048 | **t2i 上无效**（模板写死 1024），仅编辑模板生效（见 §5.1） |
| `negative_prompt` | 空 | 文本 | 出现稳定缺陷时再加，见下 |

采样器固定 **euler + simple**，不需要调；turbo 上游模板走 `KSamplerSelect` + `CFGGuider`。

### Prompt 增强（PE）模型的显存代价

`qwen3.5_9b_qwen_image_2.1_pe_t2i` / `_pe_i2i`（9B int8）**各 8.8 GB 磁盘**，实测算力显存：

| 项 | 实测（RTX 5070 Ti Laptop 12 GB） |
|---|---|
| 加载峰值 | **9.75 GB**（常驻 9.63 GB） |
| 释放后 | 1.23 GB（`/free` 立刻回收） |
| 释放后再出图 | 可正常跑（turbo 1056² 7.1 秒，峰值 11.57 GB） |

结论：

- **PE 与出图模型不能同时驻留 12 GB 卡**（PE 就要 9.75 GB），必须两段式：先加载 PE 扩写提示词 → `/free` 释放 → 再加载出图模型。
- **8 GB 显存跑不了 PE**（9.75 > 8），只能靠 `--lowvram` 交换，速度会非常慢；8G 用户建议直接用 PE 之外的写法（见 [PROMPTS.md](./PROMPTS.md)）。
- 两个 PE 模型合计 17.6 GB 磁盘，只在 `full` 包里；不装 PE 不影响文生图与参考图编辑。

### 负向提示词

模板支持（`__NEGATIVE__` 直连编码器），但**默认留空**。只在出现顽固缺陷时加，保持短：

```
文字乱码, 多余的手指, 畸变, 水印
```

堆一长串 `worst quality, low quality, bad anatomy…` 对 Qwen 收益很低。

## 3. 模板对照

| 模板 | 用途 | 关键差异 |
|---|---|---|
| `qwen_image_2_1_t2i` | 默认文生图 | 25 步，euler/simple |
| `qwen_image_2_1_t2i_turbo` | 草稿 | 内置直连走**官方 8 步协议**（`ManualSigmas` + `CFGGuider`，只要 turbo 模型）；没有 turbo 模型、但本地已有 turbo LoRA 时回退 6 步（`Qwen-Image-2.1-viggle-turbo-v0.3-6step-lora-r256`），两者都没有会报错 |
| `qwen_image_2_1_t2i_pe` | 文生图 + 服务端改写 | 多一个 `TextGenerate` 节点，把短提示词扩写成画面描述 |
| `qwen_image_2_1_turbo_official_t2i` | 上游 turbo | `ManualSigmas`（8 步）+ `CFGGuider` + `SamplerCustomAdvanced`；内置直连的 `draft` 档就是这套 |
| `qwen_image_2_1_cn` | 中文文字渲染 | 尺寸写死 1024² |
| `qwen_image_2_1_edit` | 单图编辑 | 需要 `ref_images`，`resolution` 可调 |
| `qwen_image_2_1_edit3` / `qwen_image_2_1_edit6` | 多图合成（3 / 6 张） | 同上，参考图数量不同 |
| `qwen_image_2_1_edit_pe` | 编辑 + 改写 | 编辑版 PE |
| `qwen_image_2_1_turbo_official_edit` | 上游 turbo 编辑 | turbo 链路的编辑版 |
| `qwen_image_2_1_i2i` | 图生图 | `denoise` 生效（`__DENOISE__`），其它模板写死 1.0 |
| `qwen_image_2_1_vnccs` | 姿态/构图控制 | 挂 VNCCS 姿态 LoRA |

> 传了 `ref_images` 但用 t2i 模板 → 参考图会被忽略。插件已做自动切换（见 `resolveTemplateForRefs`）。

## 4. 服务端改写（PE）

`*_pe` 模板里多一个 `TextGenerate` 节点：用户 prompt → 按 system prompt 改写成完整描述 → 再进编码器。

- system prompt 属于**外部兼容网关**（本仓库不包含，t2i 与 i2i 各一份）
- 它要求模型以"观察者"身份描述成品图：定画幅 → 开篇句（媒介/风格/主体）→ 按区域走画面 →
  画面文字逐条加引号 → 光线单独一句 → 收尾总览；输出纯英文单段 400–500 词
- 明确禁止质量词（`masterpiece`/`8K`），要求颜色带修饰、材质具体、枚举不概括
- **在 ComfyUI 里执行，不占 agent 上下文**；只在传 `template: *_pe` 时触发

## 5. 实测记录（2026-11-07，12 GB 显存笔记本 GPU；本节数据走外部网关链路，参数结论对内置直连同样适用）

方法：同一提示词、同一 seed（424242 / 777），每次只改一个变量，1056×1056，跑完记录墙钟时间。

### 5.1 `resolution` 参数在 t2i 上无效（≠ `width`/`height`）

| 设置 | 结果 | 耗时 |
|---|---|---|
| `resolution: 512` | 与基线**逐字节相同** | 23.3s |
| `resolution: 1024`（网关模板字面量） | 基线 | 27.0s |
| `resolution: 2048` | 与基线**逐字节相同** | **3.4s**（ComfyUI 图缓存命中，没重算） |

原因看模板就知道：外部兼容网关的模板文件里 `resolution` 是**字面量 1024**，
不是 `__RESOLUTION__`；只有 `edit` / `edit3` / `edit6` 用占位符。

**结论：文生图不用管 resolution（改了也不生效）；编辑模板才需要。**

### 5.2 `cfg` 高于 1.0 能用，但更慢

| cfg | 耗时 | 观感 |
|---|---|---|
| 1.0（默认） | 27.0s | 自然、肤色与毛色准确 |
| 2.0 | 40.6s | 对比与饱和略强，细节相当 |
| 3.0 | 39.3s | 更"浓"，已开始像加了滤镜 |

cfg > 1 时每步要同时算正负两条分支，**耗时约 ×1.5**。
**结论：默认 1.0；只有想要更强对比/饱和时才用 2.0，3.0 及以上不推荐。**

### 5.3 turbo 模板：质量相当，时间约 1/3

写实照片（猫，1056²）：

| 模板 | 步数 | 耗时 |
|---|---|---|
| `t2i`（standard） | 25 | 27.0s |
| `t2i_turbo`（viggle LoRA） | 6 | **9.8s** |
| `turbo_official_t2i` | 8 | **9.2s** |

中文海报（"晨光咖啡 / 每日 7:00 开门"，832×1216）：

| 模板 | 步数 | 耗时 | 文字正确性 |
|---|---|---|---|
| `t2i` | 25 | 20.6s | ✅ 正确，但多画了一排装饰斜线 |
| `t2i_turbo` | 6 | **8.2s** | ✅ 正确，画面更干净 |
| `turbo_official_t2i` | 8 | **8.3s** | ✅ 正确，标题更大更浓 |

**结论：在本次测试的写实照片与中文海报两类样例上，turbo 模板与 standard 质量同级，耗时约 1/3。**
推荐用法：**迭代用 `draft`（官方 turbo 8 步），定稿再跑 `standard`**。
中文文字在两个 turbo 模板下同样能正确渲染，不必为了文字回到 25 步。

### 5.4 引擎长跑后的一个坑

引擎连续运行约 7 小时后，文本编码节点报 `VBAR allocation failed`（CUDA 虚拟地址分配失败），
即使显存显示空闲。**处理：`comfy(action="control", op="restart")`**，重启后首张图有 7–20 秒模型加载，
之后恢复。已写入 [USAGE.md](./USAGE.md) 故障表。

## 6. 像素预算与清晰度（实测经验）

> 本节数字来自作者本机实测（12GB 级笔记本 GPU、单 seed 为主、样本量 1–9 组），属**经验值**，不是模型定律。

### 6.1 三个上限，别混在一起

| 维度 | 实测边界 | 含义 |
|---|---|---|
| 内容峰值 | 约 **4MP** | 本次单 prompt 阶梯在 4.2MP 见顶，之后回落 |
| 可用质量上限 | 约 **8MP** | 4.2→8.3MP 是平台期：买画布不买内容，1:1 观看偏软 |
| 硬上限 | 单边 **4096** / 总量约 **16.8MP**（外部网关链路下的实测限制） | 内置直连没有这条校验，超限会变成显存不足/超时；别指望超限还能出好图 |

### 6.2 甜点因内容类型而异

- **二次元/插画**：本次实测约 **1.1MP 就接近饱和**。再给 4 倍像素只换来约 +10.7% 主体锐度（平涂细节本来就少）
- **写实/照片**：本次实测到 **2048²（4.2MP）** 仍有明显收益（约 +145%），这也是默认成片尺寸选 2048² 的原因
- 本次实测单位像素细节随尺寸单调稀释（15.86 → 10.53 → 8.19）：画布越大，平摊到每像素的信息越少；
  「高开低走」（大图再降采样）在本次测试里是净损失

### 6.3 怎么设到这些尺寸

档位只预设了 1056² / 1536² / 2048²；其它尺寸用显式参数覆盖（宽高必须是 32 的倍数）：

```text
image_generate(prompt="…", width=2048, height=2048, steps=25)
image_generate(prompt="…", width=2752, height=1536, steps=25)   # 16:9 宽幅
```

### 6.4 实用结论

- 要 4MP 的观感，本次对齐测试里「**4MP 直出 + 超分**」优于「8MP 直出再缩」（两者作用不同：前者补细节，后者买画布）
- 小图路线：本次实测「**512² 直出 + 2× 超分**」优于「2048 直出再降到 512」
- **宽幅可用**：本次测试里长宽比可自由分配（4:1 超宽约同 MP 方图的 87%，8.4MP 宽幅仍健康）
- 2.5K 笔记本壁纸（2560×1600 ≈ 4.10MP）本次实测按原生分辨率直出最合适
- 二次裁切：本次盲中心裁效果很差，要按边缘密度滑窗找焦点；即便如此，**本次测试里直接生成仍优于裁切**
- 边缘能量类指标只做粗筛——它测不出边缘质量，终裁还是人眼

## 7. 放大与后处理路由

> 本节是作者本机实测的经验（样本量 1–2 组/类型，多数单图），**不是模型定律**；换内容/换引擎版本请自行复测。

固定顺序：**渲染 → 局部修复 → 2× 超分 → 降采样回目标尺寸**。超分本身已带锐化，之后不要再叠 USM（叠加 = 过锐）。

| 内容 | 本插件可用引擎 | 倍率 / 降噪 | 备注 |
|---|---|---|---|
| 二次元 / 插画 | **`cugan_pro`**（models-pro） | ×2 / ×3，降噪 0 或 3 | 本次实测最锐；要 ×4 或更稳的兼容性用 `cugan` |
| 大图保真 / 保笔触 | `waifu2x` | ×2，降噪固定 0 | 保真度最高档，适合「不想改画风」 |
| 半写实 | `waifu2x` / `waifu2x_photo` | ×2，降噪 0 | 要增强用 `cugan_pro`（×2/×3） |
| 写实照片 | `waifu2x_photo` | ×2，降噪 0 | 屏幕看图够用；打印级上 `photo_hq` ×4 |
| 明显劣化图（噪声 + JPEG 块） | `cugan` | ×2，降噪 1–3 | 降噪 1/2 只有 `cugan` ×2 支持；`cugan` ×3/×4 与 `cugan_pro` 仅 0/3；`waifu2x` / `waifu2x_photo` 固定 0（要 n1/n2 得用插件外 CLI）。本次样本少，收益属经验值 |

- **本插件不处理 alpha**：`image_upscale` 只校验文件头，不做透明通道检测，直接把 RGBA 喂给引擎可能**静默丢掉透明通道**。
  所以：成品不需要透明时，先 `image_flatten_alpha` 压到底色再放大（该工具在 `standard` 档）；
  **需要保留透明时不要用它**——把 RGB 放大后自行重新合成 alpha，或保留原始透明副本单独处理（本条为推测，未实测）
- **类型匹配比引擎家族更重要，且错配代价不对称**：本次 3/3 样本里动漫模型用在照片上保真度垫底；
  照片模型用在动漫上则「无害也无增益」（样本 n=3，属经验值）
- **降噪档**：干净图 `0` 最稳；`3` 在本次实测里体积与细节断崖式下降，建议避开；只有劣化图才上 1–3
- **名字带「保守」不等于结构保守**：某些「保守」档实测改动像素比例反而更高；怕重画人像时先小图试
- **不该放大**：透明 RGBA（见上）、文字密集的小字（会软化变形，改用无字底图 + 后加字）
- **交付策略**：优先直接交付 2× 原图（屏幕会做超采样显示）；必须定尺寸时再用 `image_resize_lanczos` 降回（`standard` 档工具）
- 除放大外还有「回归型复原（去噪/去模糊）」与「生成式复原」两条路线；后者会改写像素，接入前必须与保守档同台对照

## 8. 能力边界（这些场景会失败或明显退化）

> 同样来自本机实测（样本 1–4 组），属经验值而非定律；「不可行」只代表本次测试的做法不可行。


- **三视图 / 多视图一致性**：纯文生图各视图会漂移；逐视图走编辑模式再拼版更可靠
- **大幅姿势变化**：概率性失真，单次通过不代表所有姿势成立；用小步链式编辑或多参考图
- **拼接合成（本次测试）不可行**：两次独立生成的透视、桌沿线、窗位各自自洽，靠羽化和接缝重绘救不了；
  本次可行做法是先定背景几何、再让角色在同一 latent 内锚定（代价约多 30% 时间）
- **编辑注入是全图重绘，不是图层合成**：本次实测背景区仍有明显变化；要真图层得靠局部注入或透明层后端合成
- **自由文生图的多 seed 没有共同真值**：本次实测帧间差异极大（SSIM 0.38–0.42），朴素多帧平均会变糊；先锁结构才谈得上融合
- **参考图继承是默认行为**：道具、配角、背景杂物会被当成角色的一部分
- **程序骨架控制**（需外部兼容网关 + ControlNet/VNCCS 模型，且骨架图要自己画/用外部脚本生成，插件只提供 `pose_check` 校验）：
  骨架要黑底粗白线、实心白头、无地面线/箭头；骨架构图要校准到模型习惯位（人物重心约在画面 0.37–0.42 高度），不校准会「有些帧对不上」
- **多帧动画**：本次实测链式编辑会逐帧累积 VAE 有损往返（尾帧变暗发糊）；改为每帧从同一参考独立生成，
  并把动作措辞夸张 2–3 倍（合成用 `anim_encode`，单帧姿势可用 `pose_check` 校验）
- **显存墙**：12GB 上「角色参考 + 控制网 + 骨架」已逼近极限（视频/大模型类工作流更容易 OOM）
- **画质上限更多在链路而非模型**：本次实测 4MP 大画布的单位细节偏稀薄，交给超分补比硬提分辨率划算
