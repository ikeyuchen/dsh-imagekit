# 生图链路与参数手册

> 本文说明提示词在链路中的位置与加工方式，以及模型参数与调整方法。
> 提示词写法见 [PROMPTS.md](./PROMPTS.md)；使用流程见 [USAGE.md](./USAGE.md)。

## 1. 提示词的真实链路

插件有两条出图链路。`generationBackend=auto`（默认）会先探测外部网关：在线时使用网关，离线时使用内置直连；也可强制只使用其中一条：

| 链路 | 何时使用 | 提示词怎么进模型 |
|---|---|---|
| 内置直连（`auto` 且网关离线时自动使用） | 文生图 / 参考图编辑；无需外部服务 | 插件在 Node 里现场拼 ComfyUI API 工作流：`UNETLoader` + `CLIPLoader` + `CLIPTextEncode` → `KSampler` → `VAEDecode` → `SaveImage`；参考图编辑多一步 `/upload/image` + 编辑编码节点 |
| 外部兼容网关（旧模板） | `*_pe`（Prompt 增强）、`cn`（ControlNet）、`vnccs`、`turbo_official_edit` 等旧模板 | 网关按自己的模板文件把占位符替换成实际参数（模板不在本仓库） |

两条链路的共同点：提示词最终都以文本进文本编码器，所以本手册的参数与提示词结论对两条链路都成立；
区别仅在于是否包含 Prompt 增强与额外控制网。`generationBackend` 配置控制使用哪种链路（见 [CONFIGURATION.md](./CONFIGURATION.md)）。

## 2. 采样参数

| 参数 | 默认 | 范围/取值 | 什么时候动 |
|---|---|---|---|
| `steps` | 25 | 4–50（官方 turbo 固定 8 步；turbo LoRA 回退 6 步） | 细节不足时增加 5–10；需要更快时使用 `draft` 档（turbo 8 步约等于 standard，见 §5.3） |
| `cfg` | 1.0 | 1.0–3.0（实测） | 保持 1.0；2.0 对比与饱和度更高，耗时约 ×1.5；不建议使用 3.0（见 §5.2） |
| `width` / `height` | 由档位决定（省略 `tier` = standard 1536²；draft 1056² / quality 2048²） | 32 的倍数；模型原生 ≈4MP（2048²），官方比例表 2048²–2752×1536 | 默认档 1536²（25 步，12 GB 约 50 秒）；成片 2048²/40 步（约 170 秒）；草稿 1056²；不建议超过原生分辨率（2560²、25 步约 226 秒，且容易出现重复结构） |
| `seed` | -1（随机） | 整数 | 复现同一张：结果 meta 会回显实际 seed；只在相同尺寸/模型/步数下有效 |
| `batch_size` | 1 | 1–8 | 一次出多张再挑；显存占用线性增长 |
| `denoise` | 1.0 | 0.05–1.0 | 仅对 i2i 有效：0.4–0.6 用于轻微打磨，0.7–0.9 保留结构并修改内容，1.0 完全重画；单图且 `denoise<1` 时自动切换至 i2i |
| `resolution` | 1056（t2i 忽略） | 512–2048 | t2i 上无效（模板写死 1024），仅编辑模板生效（见 §5.1） |
| `negative_prompt` | 空 | 文本 | 出现稳定缺陷时再加，见下 |

采样器固定 euler + simple，不需要调；turbo 上游模板走 `KSamplerSelect` + `CFGGuider`。

### Prompt 增强（PE）模型的显存代价

`qwen3.5_9b_qwen_image_2.1_pe_t2i` 与 `_pe_i2i`（9B int8）各占用 8.8 GB 磁盘，实测算力显存如下：

| 项 | 实测（RTX 5070 Ti Laptop 12 GB） |
|---|---|
| 加载峰值 | 9.75 GB（常驻 9.63 GB） |
| 释放后 | 1.23 GB（`/free` 立刻回收） |
| 释放后再出图 | 可正常运行（turbo 1056² 7.1 秒，峰值 11.57 GB） |

结论：

- PE 与出图模型不能同时驻留 12 GB 显存（PE 需要 9.75 GB），必须分段执行：先加载 PE 扩写提示词，再通过 `/free` 释放，最后加载出图模型。
- 8 GB 显存无法运行 PE（9.75 GB > 8 GB），使用 `--lowvram` 交换会显著降低速度；建议 8 GB 用户采用 PE 之外的方法（见 [PROMPTS.md](./PROMPTS.md)）。
- 两个 PE 模型合计占用 17.6 GB 磁盘，仅包含在 `full` 包中；未安装 PE 不影响文生图与参考图编辑。

### 负向提示词

模板支持（`__NEGATIVE__` 直连编码器），但默认留空。只在出现顽固缺陷时加，保持短：

```
文字乱码, 多余的手指, 畸变, 水印
```

堆叠 `worst quality, low quality, bad anatomy` 等长串负向词对 Qwen 收益有限。

## 3. 模板对照

| 模板 | 用途 | 关键差异 |
|---|---|---|
| `qwen_image_2_1_t2i` | 默认文生图 | 25 步，euler/simple |
| `qwen_image_2_1_t2i_turbo` | 草稿 | 内置直连使用官方 8 步协议（`ManualSigmas` 与 `CFGGuider`，仅需 turbo 模型）；缺少 turbo 模型但本地有 turbo LoRA 时回退至 6 步（`Qwen-Image-2.1-viggle-turbo-v0.3-6step-lora-r256`），两者均缺失时返回错误 |
| `qwen_image_2_1_t2i_pe` | 文生图 + 服务端改写 | 多一个 `TextGenerate` 节点，把短提示词扩写成画面描述 |
| `qwen_image_2_1_turbo_official_t2i` | 上游 turbo | `ManualSigmas`（8 步）+ `CFGGuider` + `SamplerCustomAdvanced`；内置直连的 `draft` 档使用此方案 |
| `qwen_image_2_1_cn` | 中文文字渲染 | 尺寸写死 1024² |
| `qwen_image_2_1_edit` | 单图编辑 | 需要 `ref_images`，`resolution` 可调 |
| `qwen_image_2_1_edit3` / `qwen_image_2_1_edit6` | 多图合成（3 / 6 张） | 同上，参考图数量不同；自动切换按 2–3 张 → `edit3`、4 张以上 → `edit6` |
| `qwen_image_2_1_edit_pe` | 编辑 + 改写 | 编辑版 PE |
| `qwen_image_2_1_turbo_official_edit` | 上游 turbo 编辑 | turbo 链路的编辑版 |
| `qwen_image_2_1_i2i` | 图生图 | `denoise` 生效（`__DENOISE__`），其它模板写死 1.0；单图 + `denoise<1` 自动选它 |
| `qwen_image_2_1_vnccs` | 姿态/构图控制 | 挂 VNCCS 姿态 LoRA |

> 传了 `ref_images` 但用 t2i 模板 → 参考图会被忽略。插件已做自动切换：单图 → `edit`，2–3 张 → `edit3`，
> 4 张以上 → `edit6`，单图 + `denoise<1` → `i2i`（见 `resolveTemplateForRefs`）。直连按张数现场拼节点，模板名主要给网关用。

## 4. 服务端改写（PE）

`*_pe` 模板里多一个 `TextGenerate` 节点：用户 prompt → 按 system prompt 改写成完整描述 → 再进编码器。

- system prompt 属于外部兼容网关（本仓库不包含，t2i 与 i2i 各一份）
- 它要求模型以"观察者"身份描述成品图：定画幅 → 开篇句（媒介/风格/主体）→ 按区域走画面 →
  画面文字逐条加引号 → 光线单独一句 → 收尾总览；输出纯英文单段 400–500 词
- 明确禁止质量词（`masterpiece`/`8K`），要求颜色带修饰、材质具体、枚举不概括
- 在 ComfyUI 里执行，不占 agent 上下文；只在传 `template: *_pe` 时触发

## 5. 实测记录（2026-11-07，12 GB 显存笔记本 GPU；本节数据走外部网关链路，参数结论对内置直连同样适用）

方法：同一提示词、同一 seed（424242 / 777），每次只改一个变量，1056×1056，记录实际耗时。

### 5.1 `resolution` 参数在 t2i 上无效（≠ `width`/`height`）

| 设置 | 结果 | 耗时 |
|---|---|---|
| `resolution: 512` | 与基线逐字节相同 | 23.3s |
| `resolution: 1024`（网关模板字面量） | 基线 | 27.0s |
| `resolution: 2048` | 与基线逐字节相同 | 3.4s（ComfyUI 图缓存命中，未重新计算） |

原因是外部兼容网关的模板文件中 `resolution` 为字面量 1024，而非 `__RESOLUTION__`；只有 `edit`、`edit3`、`edit6` 使用占位符。

结论：文生图不需要设置 resolution，修改不会生效；仅编辑模板需要。

### 5.2 `cfg` 高于 1.0 能用，但更慢

| cfg | 耗时 | 观感 |
|---|---|---|
| 1.0（默认） | 27.0s | 自然、肤色与毛色准确 |
| 2.0 | 40.6s | 对比与饱和略强，细节相当 |
| 3.0 | 39.3s | 更"浓"，已开始像加了滤镜 |

cfg > 1 时每步同时计算正负两条分支，耗时约为原来的 1.5 倍。结论：默认使用 1.0；需要更高对比度或饱和度时使用 2.0，不建议 3.0 及以上。

### 5.3 turbo 模板：质量相当，时间约 1/3

写实照片（猫，1056²）：

| 模板 | 步数 | 耗时 |
|---|---|---|
| `t2i`（standard） | 25 | 27.0s |
| `t2i_turbo`（viggle LoRA） | 6 | 9.8s |
| `turbo_official_t2i` | 8 | 9.2s |

中文海报（"晨光咖啡 / 每日 7:00 开门"，832×1216）：

| 模板 | 步数 | 耗时 | 文字正确性 |
|---|---|---|---|
| `t2i` | 25 | 20.6s | 正确，但多生成了一排装饰斜线 |
| `t2i_turbo` | 6 | 8.2s | 正确，画面更干净 |
| `turbo_official_t2i` | 8 | 8.3s | 正确，标题更大更浓 |

结论：在本次测试的写实照片与中文海报两类样例上，turbo 模板与 standard 质量同级，耗时约 1/3。
推荐用法：迭代使用 `draft`（官方 turbo 8 步），定稿时使用 `standard`。
中文文字在两个 turbo 模板下同样能正确渲染，不必为了文字回到 25 步。

### 5.4 引擎长时间运行后的问题

引擎连续运行约 7 小时后，文本编码节点报 `VBAR allocation failed`（CUDA 虚拟地址分配失败），
即使显存显示空闲。处理方式为执行 `comfy(action="control", op="restart")`；重启后首张图需要 7–20 秒加载模型，之后恢复。已写入 [USAGE.md](./USAGE.md) 故障表。

## 6. 像素预算与清晰度

> 本节数据来自本机实测（12 GB 级笔记本 GPU，以单 seed 为主，样本量 1–9 组），属经验值，不是模型定律。

### 6.1 三个上限

| 维度 | 实测边界 | 含义 |
|---|---|---|
| 内容峰值 | 约 4MP | 本次单 prompt 阶梯在 4.2MP 见顶，之后回落 |
| 可用质量上限 | 约 8MP | 4.2–8.3MP 为平台期：画布面积增加，但内容细节不再增加，1:1 观看偏软 |
| 硬上限 | 单边 4096 / 总量约 16.8MP（外部网关链路下的实测限制） | 内置直连没有此校验，超限会导致显存不足或超时；超过上限无法保证质量 |

### 6.2 最佳区间因内容类型而异

- 二次元/插画：本次实测约 1.1MP 就接近饱和。增加 4 倍像素仅带来约 10.7% 的主体锐度提升（平涂细节本身较少）
- 写实/照片：本次实测到 2048²（4.2MP） 仍有明显收益（约 +145%），这也是默认成片尺寸选 2048² 的原因
- 本次实测单位像素细节随尺寸单调稀释（15.86 → 10.53 → 8.19）：画布越大，平摊到每像素的信息越少；
  先生成大图再降采样在本次测试中为净损失

### 6.3 怎么设到这些尺寸

档位只预设了 1056² / 1536² / 2048²；其它尺寸用显式参数覆盖（宽高必须是 32 的倍数）：

```text
image_generate(prompt="…", width=2048, height=2048, steps=25)
image_generate(prompt="…", width=2752, height=1536, steps=25)   # 16:9 宽幅
```

### 6.4 实用结论

- 要获得 4 MP 的观感，本次对齐测试中「4 MP 直出 + 超分」优于「8 MP 直出后缩小」。两者作用不同：前者补充细节，后者增加画布面积。
- 小图路线：本次实测「512² 直出 + 2× 超分」优于「2048 直出再降到 512」
- 宽幅可用：本次测试里长宽比可自由分配（4:1 超宽约同 MP 方图的 87%，8.4MP 宽幅仍健康）
- 2.5K 笔记本壁纸（2560×1600 ≈ 4.10MP）本次实测按原生分辨率直出最合适
- 二次裁切：本次盲中心裁效果很差，要按边缘密度滑窗找焦点；即便如此，本次测试里直接生成仍优于裁切
- 边缘能量类指标仅用于粗筛，无法测出边缘质量，最终判断仍依赖人眼

## 7. 放大与后处理路由

> 本节数据来自本机实测（每类样本量 1–2 组，多数为单图），属经验值，不是模型定律；更换内容或引擎版本后需重新测试。

固定顺序为渲染、局部修复、2× 超分、降采样至目标尺寸。超分本身已带锐化，之后不应再叠加 USM，否则会过度锐化。

| 内容 | 本插件可用引擎 | 倍率 / 降噪 | 备注 |
|---|---|---|---|
| 二次元 / 插画 | `cugan_pro`（models-pro） | ×2 / ×3，降噪 0 或 3 | 本次实测最锐；要 ×4 或更稳的兼容性用 `cugan` |
| 大图保真 / 保笔触 | `waifu2x` | ×2，降噪固定 0 | 保真度最高档，适合「不想改画风」 |
| 半写实 | `waifu2x` / `waifu2x_photo` | ×2，降噪 0 | 要增强用 `cugan_pro`（×2/×3） |
| 写实照片 | `waifu2x_photo` | ×2，降噪 0 | 可满足屏幕观看；打印级使用 `photo_hq` ×4 |
| 明显劣化图（噪声 + JPEG 块） | `cugan` | ×2，降噪 1–3 | 降噪 1/2 只有 `cugan` ×2 支持；`cugan` ×3/×4 与 `cugan_pro` 仅 0/3；`waifu2x` / `waifu2x_photo` 固定 0（要 n1/n2 得用插件外 CLI）。本次样本少，收益属经验值 |

- 本插件不处理 alpha：`image_upscale` 只校验文件头，不做透明通道检测，直接把 RGBA 喂给引擎可能静默丢掉透明通道。
  所以：成品不需要透明时，先 `image_flatten_alpha` 压到底色再放大（该工具在 `standard` 档）；
  需要保留透明时不要使用该工具：将 RGB 图放大后自行重新合成 alpha，或保留原始透明副本单独处理（本条为推测，未实测）。
- 类型匹配比引擎家族更重要，且错配代价不对称：本次 3/3 样本里动漫模型用在照片上保真度垫底；
  照片模型用在动漫上则「无害也无增益」（样本 n=3，属经验值）
- 降噪档：干净图使用 `0` 最稳定；`3` 在本次实测中使体积与细节显著下降，建议避开；仅在图像明显劣化时使用 1–3。
- 名称带「保守」不代表结构保守：部分「保守」档实测改动像素比例更高；担心人像被重画时，先在小图上测试。
- 不应放大：透明 RGBA 图（见上）与文字密集的小字（会软化变形，应改用无字底图并在后期加字）。
- 交付策略：优先交付 2× 原图，屏幕会进行超采样显示；必须固定尺寸时，再使用 `image_resize_lanczos` 降回（`standard` 档工具）。
- 除放大外还有「回归型复原（去噪/去模糊）」与「生成式复原」两条路线；后者会改写像素，接入前必须与保守档对照测试。

## 8. 能力边界

> 以下为本机实测结果（样本 1–4 组），属经验值而非定律；「不可行」仅代表本次测试的方法不可行。


- 三视图 / 多视图一致性：纯文生图各视图会漂移；逐视图走编辑模式再拼版更可靠
- 大幅姿势变化：概率性失真，单次通过不代表所有姿势成立；用小步链式编辑或多参考图
- 拼接合成在本次测试中不可行：两次独立生成的透视、桌沿线与窗位各自自洽，羽化和接缝重绘无法修复。可行做法是先确定背景几何，再让角色在同一 latent 内锚定，代价约为增加 30% 时间。
- 编辑注入为全图重绘，不是图层合成：本次实测背景区域仍有明显变化；需要真实图层时，应使用局部注入或透明层后端合成。
- 自由文生图的多 seed 没有共同真值：本次实测帧间差异较大（SSIM 0.38–0.42），简单多帧平均会导致模糊；应先锁定结构，再考虑融合。
- 参考图继承是默认行为：道具、配角与背景杂物会被视为角色的一部分。
- 程序骨架控制：需要外部兼容网关、ControlNet 或 VNCCS 模型，骨架图需自行绘制或由外部脚本生成，插件只提供 `pose_check` 校验。骨架应为黑底粗白线、实心白头，不含地面线与箭头；骨架构图需校准至模型常用位置（人物重心约在画面高度 0.37–0.42），否则部分帧无法对齐。
- 多帧动画：本次实测链式编辑会逐帧累积 VAE 有损往返，尾帧变暗发糊；应改为每帧从同一参考独立生成，并将动作描述强化 2–3 倍（合成使用 `anim_encode`，单帧姿势可用 `pose_check` 校验）。
- 显存限制：12 GB 显存下「角色参考 + 控制网 + 骨架」已接近上限，视频或大模型工作流更容易出现 OOM。
- 画质上限更多取决于链路而非模型：本次实测 4MP 大画布的单位细节偏稀薄，使用超分补充比直接提高分辨率更有效。
