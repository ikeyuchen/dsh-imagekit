# 提示词手册（探索版）

> 提示词文档分为两层，不互相复制：
>
> | 层 | 位置 | 加载方式 | 用途 |
> |---|---|---|---|
> | 内置版 | 本仓库 `docs/PROMPTS-CORE.md`（随包分发） | `image_prompt_guide` 按需返回，不占常驻上下文 | 日常出图使用的配方与限制 |
> | 仓库（探索版） | 本文件 `docs/PROMPTS.md` | 随包分发，不占 agent 上下文 | 探索模型能力边界，记录可复现的实验结论 |
>
> 约定：配方类速查放内置版；本页仅保留长期有效的探索结论与方法。新增提示词文件也放 `docs/`，命名 `PROMPTS*.md`。
> 规则以 [PROMPTS-CORE.md](./PROMPTS-CORE.md) 为准；本页仅保留实验差异与出处，不重复同一套规则。

> 数据口径：本页数字来自作者本机实测。多数实验为单 seed、单张图（少数 3–4 seed），
> 属经验值而非普适规律；更换模型、版本或内容后可能不成立。作为结论使用前需复现。

## 一、通用骨架

提示词应为连贯的画面描述，而非关键词堆叠。Qwen 适合自然语言描述，应说明颜色、形状、大小、材质、数量、文字与空间关系。

```
主体（是什么/几个） → 场景（在哪） → 风格 → 构图与光线 → 文字（要出字才写）
```

- 首句定画种与主体，风格词只出现一次；随后用 8–14 个方位短语铺开画面，覆盖四角与中心，不要全堆在中间
- 颜色带修饰词（深藏青、灰橄榄、淡奶油），材质写具体（拉丝金属、磨砂玻璃、粗麻）；光照单独成句，结尾一句收构图
- 陈述句优于祈使句；不要堆叠「8K / masterpiece / award-winning」等质量词。这类词对 Qwen 效果有限，只会占用提示词语义
- 标签化短行仅用于规划；提交前展开为连贯描述，不要把标签写入 prompt。
- 画幅用 `width` / `height`，不要写 `--ar`（见 [MODEL.md](./MODEL.md)）

## 二、按内容选配方

### 写实照片

- 摄影术语主要提升照片质感，不直接提升锐度：本次矩阵里 `85mm`、`眼部对焦`、`浅景深` 让画面更像照片，但主体锐度并不高
- 需要极限锐度时使用摇拍描述：`主体清晰 + 背景水平动态模糊`（本次实测主体锐度最高）
- 需要突出主体时增加景深描述（背景虚化）：本次实测主体/背景锐度比明显上升，主体绝对锐度并没有跟着涨
- 胶片颗粒会制造假高频，跨风格比较时不可信

### 二次元插画

- 关键词族：`赛璐璐上色`、`干净线稿`、`平涂`、`水彩动漫`、`复古 90 年代赛璐璐`；`upper body` / `full body` 控制取景
- 背景必须显式指定：`平涂色块 + 无笔触 + 平滑渐变`；否则模型倾向于厚涂风格。
- 两条美学路线均成立，先确定路线再调整参数：舒适型（低信息密度 + 统一影调 + 极简构图 + 单主体）与冲击型（高锐度 + 超分增强）
- 角色一致性优先走编辑模式（参考图 + 姿势/场景描述）；纯文生图做三视图，各视图会漂移

### 3D / 产品

- 手办/人偶：`可动人偶 + 比例 + PVC 光泽 + 布料哑光 + 影棚光 + 产品摄影 + 浅景深`
- 纯产品：换成「材质台面 + 中性背景 + 柔光箱顶光」
- 产品图不要从 512² 开始：512 → 1056² 时主体锐度与主体/背景比均明显改善。

### 海报 / 带文字

- 先确定版式，再处理文字：标题位置、逐字引号文本、字重与颜色、插图区域
- 比例用数字比用形容词可靠：单字宽约画宽的 7%、文本列宽 15–18%
- 要求「画与字并重」时写「比例协调」，不要写「某元素最重要」
- 中文文字应逐字加引号，并注明不得多字、漏字、错字或乱码。
- 更稳定的工程路线：先生成无字底图，再后处理，最后在设计层添加文字（放大或后处理会使小字轻微软化）。

### 图标 / 小尺寸贴纸

- 小图不要采用「大尺寸生成后降采样」：本次对齐测试中，512² 直出加 2× 超分往返优于 2048² 直出后缩小，速度也更快。
- 透明底使用明确的 RGBA 句式（`透明背景` 加主体描述），直出 alpha 通常可用；
  需要合成或扁平化时使用 `image_flatten_alpha`（该工具在 `standard` 档）。
- 小尺寸观感主要取决于中频边缘对比，而非高频细节；堆叠细节容易被看图软件降采样消除。

## 三、文字渲染

- 步数决策见 [CORE §3](./PROMPTS-CORE.md)：25 步起步，出错再升 40，密集再上 `cfg 2`。
- 本页实验：同一 seed、2048² 下，40 步的 OCR 正确率高于 25 步；十余行小字有时在 25 步时已无错误。
- 排版档耗时约为 1.2–2.4 倍；并非所有文字任务都需要，应根据结果决定。
- 没有统一的「超过多少字必崩」阈值：可追溯的只有行数级案例；高难排版仍会出错，不能当保证
- 数字与相似字形属于字符级混淆：同一 seed 下两档均会出错，应更换 seed 或将数字改写为汉字。
- 生僻字不要仅依赖一次 OCR：结合多次读数、位置与提示词引用交叉验证。
- 目标分辨率远超模型训练尺度时会降低提示词遵循度，分辨率并非越大越好。

## 四、参考图编辑

- 显式枚举需要保留的属性，细化到部件级别（例如耳朵的内外轮廓、领结、裙摆）；易漂移属性加 `MUST stay`。
  没写进提示词的属性 = 模型自由发挥的空间
- 优先描述正向状态：手持道具、配角、宠物与背景杂物会被继承；使用「双手自然垂在身侧，掌心空着」
  「画面只有一个角色」等描述，比堆叠「无任何道具 / 无吉祥物」更稳定（官方旧版改写器不建议使用否定词）。
  需要排除时使用 `negative_prompt`（cfg > 1 时生效）。
- 多图使用索引与职责限定：图 1 只负责角色，图 2 只负责风格或背景；每次只修改一个层级。
- 同一角色的多张不同角度参考会复制出多个角色；一致性场景应使用单一权威参考，并通过文字描述目标姿态。
- 换背景是本次实测中保留角色最稳定的编辑路径。纯白底参考会使整个场景偏白，应改用两段式流程：先生成干净角色，再单独更换背景。
- 参考图必须是像素级真相：从自己的设计稿图层直接取素材，不要靠打标或看图描述推断
- 含 alpha 的图应先扁平化：原生分辨率下 alpha 噪声会被继承；按像素预算重采样可同时平均噪声。
- 高风险场景：大幅姿势变化存在概率性失真，应使用小步链式编辑或多参考图；翻拍参考图的透视倾斜、截断、相邻内容与光照不均会被忠实复刻，需先裁边补边并明确排除。
- 复杂动作拆成可验证锚点（坐深、躯干角、腿伸向、手位、头仰角、眼开度、嘴形），比「瘫坐伸腿」这类笼统词可控
- 交付前使用双种子生成候选，逐项验收后定稿。

## 五、常见错误

- 不得把 Markdown 或项目符号写入 prompt，模型会将其当作画面文字。
- 不得一次放入 5 个主体与 3 种风格，元素会相互干扰，结果趋于平庸。
- 不要期望一次生成准确的长文案；超过约 20 字时应分批生成或后期排版。
- 不要使用 `--ar`，也不要堆叠 `masterpiece`、`8k` 等低收益标记。
- 不要把提高分辨率作为清晰度方案，参见 [MODEL.md](./MODEL.md) 的像素预算。
- 不要在参考图中写风格断言，否则会使角色或画面偏离参考。
- 不要在小尺寸图中堆叠高频细节，降采样会使其消失。
- 不要在多轮编辑后直接交付同一张图，软化与偏色会累积。
- 不要仅依据一次 OCR 判断文字正确性。

## 六、能力边界实验

固定变量，每次只改变一个维度，结论才可复现：

1. 固定 seed（如 `seed=888`），只改提示词：判断「是措辞问题还是模型不会」
2. 文字长度阶梯：`4 字 → 8 字 → 12 字 → 20 字 → 30 字`，找出该尺寸下还能写对的长度
3. 主体数量阶梯：`1 → 2 → 3 → 5` 个主体，看从第几个开始互相污染
4. 尺寸 × 步数矩阵：同一提示词在 `1056²/1536²/2048²` × `8/25/40` 步各出一张，判断「细节不足」是分辨率问题还是步数问题
5. 放大是否值得：同图 `image_upscale` ×2 与原生 2048² 对比，看是「结构不足」还是「只是不够锐」

记录格式建议：`提示词 / 尺寸 / 步数 / seed / 结论（能/不能，边界在哪）`。
单张图不足以形成结论。至少使用 3–5 个 seed 或 3 类不同内容复现后，再写入本文档。
