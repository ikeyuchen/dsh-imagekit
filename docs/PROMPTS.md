# 提示词手册（探索版）

> **提示词相关文件只分两层，不要互相复制**：
>
> | 层 | 位置 | 加载方式 | 用途 |
> |---|---|---|---|
> | 内置（简洁版） | DSH 技能 `qwen-image-cookbook`（**不在本仓库**） | 按需加载，受上下文预算限制 | 日常出图够用的配方与禁忌 |
> | 仓库（探索版） | 本文件 `docs/PROMPTS.md` | 随包分发，**不占 agent 上下文** | 摸模型能力上限、沉淀可复现的实验结论 |
>
> 约定：配方类速查放内置版；这里只写「值得长期沉淀的探索结论 + 方法」。新增提示词文件也放 `docs/`，命名 `PROMPTS*.md`。

> **数据口径**：本页数字来自作者本机实测。多数实验是**单 seed、单张图**（少数 3–4 seed），
> 属于「经验值」而不是普适规律；换模型/换版本/换内容都可能不成立。需要当结论用之前先复现。

## 一、通用骨架

**把它写成一句画面描述，不是关键词堆。** Qwen 吃 caption——描述颜色、形状、大小、材质、数量、文字、空间关系。

```
主体（是什么/几个） → 场景（在哪） → 风格 → 构图与光线 → 文字（要出字才写）
```

- 首句定画种与主体，风格词只出现一次；随后用 8–14 个方位短语铺开画面，覆盖四角与中心，不要全堆在中间
- 颜色带修饰词（深藏青、灰橄榄、淡奶油），材质写具体（拉丝金属、磨砂玻璃、粗麻）；光照单独成句，结尾一句收构图
- **陈述句**优于祈使句；不要堆「8K / masterpiece / award-winning」这类质量咒语——对 Qwen 无效，只挤占语义
- 标签化短行（用途 / 主体 / 风格 / 构图 / 光照 / 色板 / 材质 / 文字 / 约束）比 200 词长段落更好改：迭代时只动一行
- 画幅用 `width` / `height`，不要写 `--ar`（见 [MODEL.md](./MODEL.md)）

## 二、按内容选配方

### 写实照片

- 摄影术语买到的是「照片质感」而非锐度：本次矩阵里 `85mm`、`眼部对焦`、`浅景深` 让画面更像照片，但主体锐度并不高
- 想极限锐利用**摇拍语言**：`主体清晰 + 背景水平动态模糊`（本次实测主体锐度最高）
- 要突出主体就加景深措辞（背景虚化）：本次实测主体/背景锐度比明显上升，主体绝对锐度并没有跟着涨
- 胶片颗粒会制造假高频，跨风格比较时不可信

### 二次元插画

- 关键词族：`赛璐璐上色`、`干净线稿`、`平涂`、`水彩动漫`、`复古 90 年代赛璐璐`；`upper body` / `full body` 控制取景
- **背景必须主动指定**：`平涂色块 + 无笔触 + 平滑渐变`，否则默认往厚涂抹走
- 两条都成立的美学路线，先定路线再调参：**舒适型**（低信息密度 + 统一影调 + 极简构图 + 单主体）与**冲击型**（高锐度 + 超分增强）
- 角色一致性优先走编辑模式（参考图 + 姿势/场景描述）；纯文生图做三视图，各视图会漂移

### 3D / 产品

- 手办/人偶：`可动人偶 + 比例 + PVC 光泽 + 布料哑光 + 影棚光 + 产品摄影 + 浅景深`
- 纯产品：换成「材质台面 + 中性背景 + 柔光箱顶光」
- 产品图别从 512 上来：512 → 1056² 的主体锐度提升明显，主体/背景比也明显变好

### 海报 / 带文字

- **先版式后文字**：标题位置 → 逐字引号文本 → 字重/颜色 → 插图区域
- 比例用数字比用形容词可靠：单字宽约画宽的 7%、文本列宽 15–18%
- 要求「画与字并重」时写「比例协调」，不要写「某元素最重要」
- 中文逐字引号 + 「不得多字/漏字/错字/乱码」每次都要带
- 工程上更稳的路线：**先生成无字底图 → 后处理 → 在设计层加字**（放大或后处理会让小字轻微软化）

### 图标 / 小尺寸贴纸

- 小图别「大预算 + 降采样」：本次对齐测试里 512² 直出 + 2× 超分往返，比 2048 直出再缩更好也更快
- 透明底用明确的 RGBA 句式（`透明背景` + 主体描述），直出 alpha 通常可用；
  要合成/扁平化用 `image_flatten_alpha`（该工具在 `standard` 档）
- 小尺寸观感更取决于**中频边缘对比**而非高频细节：堆细节容易被看图软件降采样抹平

## 三、文字渲染（最容易低估的一环）

- 含文字的图优先 **40 步**：同 seed、2048² 下，40 步的 OCR 正确率高于 25 步；25 步适合无文字快速迭代
- 密集小字再上「排版档」：`cfg 2` + 40 步 + 负向词。代价约 1.2–2.4× 时间，但错字与幻觉字块更少
- 中等难度（十来行小字）有时 cfg 1 / 25 步就已零错——**先试默认档，再按结果升档**，不要一律堆 40 步
- 没有统一的「超过多少字必崩」阈值：可追溯的只有行数级案例；高难排版仍会出错，不能当保证
- 数字与相似字形是**字符级混淆**：同 seed 两档会同错，换 seed 或把数字改写成汉字更稳
- 生僻字不要单信一次 OCR：用多次读数 + 位置 + 提示词引用交叉验证
- 目标分辨率远超模型训练尺度会丢提示词遵循——不是越大越好

## 四、参考图编辑

- **显式枚举要保留的属性**，细到部件级别（比如耳朵的内外轮廓、领结、裙摆）；易漂属性加 `MUST stay`。
  没写进提示词的属性 = 模型自由发挥的空间
- **反向约束同样必须写**：手持道具、配角/宠物、背景杂物都会被继承，要点名排除
  （`双手空着，无任何道具` / `画面内只有一个角色，无吉祥物/宠物`）
- **多图用索引 + 职责限定**：图 1 只负责角色，图 2 只负责风格/背景；一次只改一层
- **同一角色多张不同角度参考会「复制」出多个角色**；一致性场景用单一权威参考 + 文字描述目标姿态
- 换背景是本次实测里「尽量保持角色」最稳的编辑路径；纯白底参考会把整个场景拉白，改用两段式：先出干净角色，再单独换背景
- 参考图必须是**像素级真相**：从自己的设计稿图层直接取素材，不要靠打标或看图描述推断
- 带 alpha 的图先扁平化再喂：原生分辨率下 alpha 噪声会被继承；按像素预算先重采样能顺带把噪声平均掉
- **易翻车场景**：大幅姿势变化（概率性失真，用小步链式编辑或多参考）、翻拍参考图（透视倾斜/截断/邻居内容/光照不均会被忠实复刻，需先裁边补边并显式排除）
- 复杂动作拆成可验证锚点（坐深、躯干角、腿伸向、手位、头仰角、眼开度、嘴形），比「瘫坐伸腿」这类笼统词可控
- 交付前双种子出候选、逐项验收再定稿

## 五、九不要

- ❌ 把 Markdown、项目符号塞进 prompt（模型会当成画面上的文字）
- ❌ 一次塞 5 个主体 + 3 种风格（互相打架，结果平庸）
- ❌ 指望一次出准长文案（超过约 20 字就该分批生成或后期排版）
- ❌ 用 `--ar` / `masterpiece` / `8k` 之类的无效标记
- ❌ 把「提高分辨率」当清晰度方案（见 [MODEL.md](./MODEL.md) 的像素预算）
- ❌ 在参考图里写风格断言（会把角色/画面带偏）
- ❌ 对小尺寸图堆高频细节（会被降采样抹平）
- ❌ 连续多轮在同一张图上编辑后直接交付（会累积软化与偏色）
- ❌ 只信一次 OCR 判断文字正确性

## 六、能力探索：怎么把上限摸出来

固定变量、一次只动一个维度，结论才可复现：

1. **固定 seed**（如 `seed=888`），只改提示词：判断「是措辞问题还是模型不会」
2. **文字长度阶梯**：`4 字 → 8 字 → 12 字 → 20 字 → 30 字`，找出该尺寸下还能写对的长度
3. **主体数量阶梯**：`1 → 2 → 3 → 5` 个主体，看从第几个开始互相污染
4. **尺寸 × 步数矩阵**：同一提示词在 `1056²/1536²/2048²` × `6/25/40` 步各出一张，判断「细节不足」是分辨率问题还是步数问题
5. **放大是否值得**：同图 `image_upscale` ×2 与原生 2048² 对比，看是「结构不足」还是「只是不够锐」

记录格式建议：`提示词 / 尺寸 / 步数 / seed / 结论（能/不能，边界在哪）`。
**单张图不算结论**——至少 3–5 个 seed 或 3 类不同内容复现过，再写回本文件。
