## 一、速查（够日常用）

**一句话：写成一句画面描述，不是关键词堆。** Qwen 吃 caption——官方模板原话是"描述颜色、形状、大小、材质、数量、文字、空间关系"。

```
主体（是什么/几个） → 场景（在哪） → 风格 → 构图与光线 → 文字（要出字才写）
```

| 密度 | 例子 |
|---|---|
| 太简 | `一只猫` |
| **刚好** | `一只橘白相间的短毛猫坐在浅色木质窗台上，午后阳光从左侧斜射进来，毛发有轮廓光，背景虚化的绿植，写实摄影，浅景深` |
| 过载 | `masterpiece, 8k, 1cat, orange cat, window, sunlight, bokeh, --ar 3:2` |

三条规则：

1. **写具体的**：「莫兰迪灰蓝」>「好看的颜色」；「三个」>「若干」；「磨砂玻璃」>「高级材质」
2. **文字加引号**：`标题写着 "夏日特惠"`，原文照抄；不要写「一段文字」
3. **别写无效标记**：`--ar 3:2`、`masterpiece`、`8k`、`ultra detailed` 对 Qwen 不起作用，只挤占语义。画幅用 `width`/`height`；要透明底写 `透明背景`

## 二、场景补充一句话

| 场景 | 再加一句 |
|---|---|
| 写实照片 | `50mm 定焦，柔和侧逆光，浅景深` |
| 插画/动漫 | `扁平矢量插画，2px 描边，低饱和暖色` |
| 产品图 | `磨砂金属机身，浅灰台面，柔光箱顶光，带投影` |
| 海报/带字 | `竖版，上方大号标题 "新品上市"，下方细体副标题` |
| 图标/logo | `单色线性图标，24 网格，2px 描边，圆头，无渐变` |

## 三、九不要

- ❌ 把 Markdown、项目符号塞进 prompt（模型会当成画面上的文字）
- ❌ 一次塞 5 个主体 + 3 种风格（互相打架，结果平庸）
- ❌ 指望一次出准超过 20 字的长文案（分批生成或后期排版）

## 四、改图

用 `<image1>` `<image2>` 指代参考图（顺序 = `ref_images` 顺序）。说清"改什么 + 什么保持不变"，只说"改 X"模型会顺手重绘别处：

```
以 <image1> 为底图保持构图与背景，把 <image2> 的人物换进画面，其余保持不变
```

负向提示词默认留空；只在出现稳定缺陷时加，且要短：`文字乱码, 多余的手指, 畸变, 水印`。

## 五、能力探索：怎么把上限摸出来

固定变量、一次只动一个维度，结论才可复现：

1. **固定 seed**（如 `seed=888`），只改提示词：用来判断"是措辞问题还是模型不会"。
2. **文字长度阶梯**：`4 字 → 8 字 → 12 字 → 20 字 → 30 字`，找出该尺寸下还能写对的长度；超过就改成分批生成 + 排版。
3. **主体数量阶梯**：`1 → 2 → 3 → 5` 个主体，看从第几个开始互相污染，而不是凭感觉说"多主体不行"。
4. **尺寸 × 步数矩阵**：同一提示词在 `1056²/1536²/2048²` × `6/25/40` 步各出一张，判断"细节不足"是分辨率问题还是步数问题。
5. **放大是否值得**：同图 `image_upscale` ×2 与原生 2048² 对比，看是"结构不足"（放大没救）还是"只是不够锐"（放大有效）。

记录格式建议：`提示词 / 尺寸 / 步数 / seed / 结论（能/不能，边界在哪）`。只把重复验证过的结论写回本文件，单次效果好看的样张不算结论。
